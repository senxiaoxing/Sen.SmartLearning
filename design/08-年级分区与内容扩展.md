# 08 · 年级分区与内容扩展

> **这份文档管什么**：答题内容如何按年级划分、题目从哪来、扩年级时哪些东西要跟着动。
>
> **不管什么**：具体每个年级教什么知识点（那是 [01-知识点图谱](01-知识点图谱.md) 逐年级扩写的事）；
> 语音的生成与打包机制（[07-音频方案](07-音频方案.md)）。

---

## 0. 一句话

**年级是内容的分区键，不是难度参数。** 一年级和三年级不是同一批知识点的难易差异，
是两批不同的知识点；而孩子的**实际水平**由摸底决定，与她在读几年级是两回事。

---

## 1. 三条核心取舍

### 1.1 ⭐ 年级是「新内容的天花板」，不是「内容的围墙」

这条决定了调度器的实现方式，是整份文档最重要的一条。

三年级的「两位数乘法」前置是二年级的「乘法口诀」。若按年级硬过滤 mastery，
`findWeakestPrerequisite()` 的回退机制会直接失效——孩子在乘法上连错，
调度器想退回口诀表，却发现那个知识点被年级墙挡在外面。
而**回退恰恰是这个项目诊断能力的落点**。

| 池子 | 按年级过滤？ |
|---|---|
| `ahead` —— 前沿**之后**的新知识点 | ✅ 只取当前年级 |
| `behind` —— 前沿**之前**遗漏的知识点 | ❌ 不过滤 |
| `review` · `confidence` · `remedial` · 前置回退 | ❌ 不过滤，允许跨年级往下 |

⭐ 一句话概括：**年级天花板只挡超前，不挡补漏。**

`behind` 之所以不挡，是因为它只在「前沿之后已无内容可学」时才启用，
那时取到的是低年级的真实缺口——语义上更接近补救而不是「开新内容」。
挡住它会让 ahead 空了之后学习池只剩已在学的几个，一直空转。

「学习前沿 frontier」的语义天然延伸——它本来就是「已掌握内容里最靠后的」，跨年级照样成立。

### 1.2 生成器是主力，题库不是它的替代品

分界线不是年级，是**题型**：

| 题型 | 生成器 | 随年级变化 |
|---|---|---|
| 计算（口算、笔算、混合运算、简算、解方程） | ✅ 越往后越强 | 题量需求**增大**，误区更清晰 |
| 单位换算、时间、数的认识 | ✅ 参数化即可 | 基本不变 |
| 图形（周长面积、立体） | ⚠️ 要配 SVG | 成本上升但可控 |
| **情境应用题** | ❌ 模板会被看穿 | **占比大幅上升，真正的坎** |
| 阅读理解、开放题 | ❌ 完全无能 | 见 §8 |

二年级的乘法口诀、表内除法、100 以内加减、长度单位——生成器不但够用，
**而且比题库好**：81 条口诀是有限集合，除法是它的逆，误区清清楚楚，题量无限。
生成器在计算这块的优势是**随年级扩大**的。

⛔ **不要从网上扒题库直接导入答题区**，三个理由：

1. ⭐ **它会废掉诊断系统**。现成题库的错误选项没有 `misconceptionTag`，
   导进来 `Attempt.misconceptionTag` 只能填空——错题本、定向补救、前置回退、
   家长报告的误区卡片**全线失效**。见 CLAUDE.md「干扰项必须有诊断性」。
2. **格式转换成本远超直觉**。权威的是 PDF 扫描件，好扒的质量差。
   OCR + 公式解析 + 图形还原之后，**还得人工给每个干扰项标误区**——
   标注这一步的工作量和直接出题差不多。
3. **语音会爆**。生成器的题靠 `ttsParts` 拼片段，无限题量只要有限片段；
   静态题是一题一条 mp3。

✅ **可以抄的是「结构」不是「题」**。数学题型的结构是公有知识，
拿试卷当「该出什么题」的参考完全没问题——那正是 §4.2 情境骨架的来源。

⚠️ 仓库是公开的 GitHub Pages，`dist/` 里的任何题库文件都可公开访问，
「纯自用」这个前提在那一刻不再成立。

### 1.3 语音包到二年级为止

**规则本身写在 CLAUDE.md 产品红线**「语音包到二年级为止，三年级起自己读题」，
此处只记它对内容扩展的两个影响：

- **二年级是语音工作的最后一站**。宠物 G2 三只的台词、二年级题干片段，
  做的时候要一次做透——之后不会再回来了。做完 `voiceManifest` 即**封版**。
- **三年级起「科目开放」的判据变了**：不再要求「有语音」，只要求「出得了题」。
  `pets.test.ts` 那条断言要按年级分。

## 2. 数据与图谱

### 2.1 `Grade` 扩容

`domain/types.ts`：`Grade` 从 `'1A' | '1B'` 扩到 `'1A' … '6B'`。
`GradeLevel`（G1~G6）与 `gradeLevelOf()` **一个字都不用改**——后者已经是 `charAt(0)`。

`Profile.grade` 字段已存在，无需新增。

### 2.2 ⭐ order 分配表

`KnowledgePoint.order` 现在是全局唯一递增整数、三科靠 `startOrder` 手工错开。
加到 6 个年级后手分必然撞车，而 **`frontier` 是靠 order 比大小的**——
同一科目内跨年级必须严格递增，否则二年级内容会被判成「前沿之前的遗漏」。

新建 `data/seed/gradeOrder.ts`：

```
ORDER_BASE: Record<Subject, Record<GradeLevel, number>>

math     G1: 1000   G2: 2000   G3: 3000   G4: 4000   G5: 5000   G6: 6000
pinyin   G1: 11000  G2: 12000  …
english  G1: 21000  G2: 22000  …
```

每个 `(科目, 年级)` 有 1000 的空间，够用且留足插入余地。

⚠️ 这会改动现有 order 值（math G1 现在从 1 起）。**是安全的**：
order 只存在 `db.knowledgePoints`，`syncStaticContent()` 是 `bulkPut` 覆盖式写入；
`mastery` 不存 order；`frontier` 只比相对大小。
但**必须递增 `CONTENT_VERSION`**，否则 `syncStaticContent()` 会直接 return 不更新。

### 2.3 seed 文件按「年级 × 科目」拆

`mathKnowledgePoints.ts` → `mathG1KnowledgePoints.ts` / `mathG2KnowledgePoints.ts` …
`knowledgePoints.ts` 继续做聚合与校验（它不是 barrel file，有实际逻辑）。

理由是文件规模上限，以及「打开单个文件就能看到全部上下文」。

新增索引：`KNOWLEDGE_POINTS_BY_GRADE: Record<GradeLevel, KnowledgePoint[]>`。

### 2.4 新增两条图校验

`validateKnowledgeGraph()` 加：

- ⭐ **`prerequisite_order_inverted`：前置的 order 必须小于自己。**
  加了年级之后这个错会真的发生——三年级知识点误挂一个四年级前置，
  结果是它**永远解锁不了**，而且不报错、不崩溃，只是那个知识点静默消失。
- **跨年级前置合法**，不要禁。跨**科目**前置仍然禁止（现有校验不动）。

`knowledgePoints.test.ts` 加：每个 `(subject, gradeLevel)` 的 order 区间互不重叠；
同科目内年级序与 order 序一致。

### 2.5 `Attempt` 加来源字段

```ts
/** 这次作答来自哪。缺失即视为 'practice'（旧数据） */
source?: 'practice' | 'quiz'
```

- `practice` —— 正常答题，进 `misconceptionCounts`
- `quiz` —— 单元测评（§9），题目来自题库、**没有 `misconceptionTag`**，
  ⛔ 只计对错，**不进误区统计**，否则会把定向补救的触发阈值稀释掉

⭐ **不需要升 `SCHEMA_VERSION`**：可选字段且不建索引，Dexie 的 `stores()` 定义不用动。
理由同 `Profile.aliases`，见 `domain/types.ts` 该字段的注释。

## 4. 生成器策略

### 4.1 ⭐ 判据是「误区清单是不是新的一套」

```
20 以内加法 → 100 以内加法
  误区还是 no_carry / carry_lost / op_confusion
  → 同一个 arithmetic 生成器，扩 params，不新建文件

加法 → 乘法
  误区是全新的：mul_as_add（3×4 算成 3+4）、口诀串行
  → 新生成器 + 新的 MisconceptionTag
```

**能复用旧干扰项策略的就复用旧生成器；需要新 `MisconceptionTag` 的才是新生成器。**

推论：扩年级的真正工作量在 `MisconceptionTag` 联合类型和图谱的 `mis` 字段上，
不在生成器文件数上。分数、小数、方程各自都是一整套新误区。

### 4.2 ⭐ 情境应用题 → 情境骨架 + 参数化

不扒题，扒**骨架**。新建 `data/seed/storyFrames.ts`：

```ts
{
  kpId: 'M2-4.3',
  frame: '{who} 有 {a} 元，买 {thing} 花了 {b} 元，还剩多少钱？',
  slots: { who: NAMES, thing: GOODS },   // 有限词表 → 语音片段可预生成
  op: 'sub',
  misconceptions: ['add_instead', 'wrong_operation'],
}
```

一个骨架 × 数值范围 × 人物/物品替换 = 几百道题，而且：

- ✅ 干扰项仍按误区生成（诊断能力保住）
- ✅ 语音仍靠片段拼（词表有限，几十条 mp3 覆盖全部骨架）
- ✅ 骨架数量可控——一个知识点 10~20 个就够，且**可以照着试卷抄结构**

现有 `domain/generators/storyProblem.ts` 已是这个思路的雏形，
只是情境写死在代码里。改造 = 把情境提成数据表。

⭐ **先在一年级 M9 上做原型**再铺到二年级——那样能在真机上比出「骨架法产的题」
和「现在直接产的题」手感差多少。

### 4.3 题型多样化是硬规则

规则写在 CLAUDE.md「题型必须多样」：**二年级起每个知识点 ≥2 条模板且题型不同**，
由 `itemTemplates.test.ts` 强制。一年级维持现状不追溯。

机制是现成的 `altTpl()`（`M7.1` 的「认图形 + 数积木」就是范例）。

### 4.4 生成器目录：什么时候才拆

`domain/generators/` 已在第 3 层，文件必须继续**扁平**，
且 ⛔ **不加年级前缀**（`mulTable.ts` 而不是 `g2MulTable.ts`）——
同一个 `arithmetic` 会同时服务 G1 和 G3，年级是内容组织，不是算法属性。

**重新审视的信号**：`GENERATORS` 注册表超过约 60 条时（现在 32 条），
按**科目**拆成 `domain/mathGenerators/` / `domain/pinyinGenerators/` /
`domain/englishGenerators/`（仍是 3 层），`domain/generators/index.ts` 只做合并。

## 5. 宠物

### 5.1 成长曲线参数按 `GradeLevel` 配置

`LEVEL_THRESHOLDS` 现在按一年级的题量校准（约 1400 题 ≈ 140 轮 → 满级 3000 exp）。
六年级内容量大得多，同一套曲线套上去，很可能**学到半学期就满级，剩下半年宠物毫无反应**。

这是「逻辑错了在 iPad 上肉眼看不出来」的典型，必须由测试守住。

- `LEVEL_THRESHOLDS` → `Record<GradeLevel, readonly number[]>`
- `growth.test.ts` 对**每个已开放年级各跑一遍**「满级 ≈ 学完一个年级」的校验
- 两端仍要守住：**第二轮就能变身**、**满级 ≈ 学完一个年级**（CLAUDE.md 宠物红线第 8 条）

### 5.2 【我的伙伴】分年级，旧宠物存档为回忆

`types.ts` 里写着旧宠物「保留在『回忆』里不再成长」，但**「回忆」这个地方目前不存在**——
孩子养到满级的团团，升年级那天会直接从首页消失。这比失去语音伤人得多。

- `PetHome`（我的伙伴页）加年级切换，**复用 `components/VolumePicker.tsx`**
- 当前年级：正常成长；往届年级：**只读展示**，保留名字、最终形态、满级徽记
- ⛔ 往届宠物**不显示经验条、不显示「还差多少升级」**——它已经完成了，
  再挂一个永远走不完的进度条等于告诉她「你当年没养满」
- ⚠️ 宠物红线第 3 条（三只之间不比较）同样适用于**跨年级**：
  不写「二年级的团团比一年级的高」，不并列进度

## 6. 入口与升年级

### 6.1 首页

```
       🐧  🐲  🐼
    小恩宝，早上好呀

    ┌─────────────┐
    │  开始学习    │   ← 主按钮永远直接进当前年级
    └─────────────┘

     1️⃣    2️⃣    3️⃣     ← 只在开放年级 > 1 时才出现
```

- **复用 `VolumePicker`**，和识字墙、诗单同一个动作、同一套 1️⃣2️⃣3️⃣ 图。
  她在那两处已经学会「按数字换一批」，这里原样再用一次。
- **只在开放年级多于一个时出现**，与 `SubjectPicker`「只在开放科目多于一个时才出现」
  完全同构。当前一年级用户的首页**一行都不变**。
- 未开放年级：显示但禁用 +「还在准备中」。理由同宠物红线第 4 条——
  诚实的预期好过空入口，也好过让她以为是自己没解锁。

⚠️ **必须拆开两个概念**（现在是同一个值）：

| | 含义 | 谁改 |
|---|---|---|
| `Profile.grade` | 她在读几年级（档案事实） | 家长区，一年一次 |
| `sessionStore.gradeLevel` | 这次要学哪个年级 | 首页切换器，默认等于前者 |

### 6.2 家长手动改 grade

⛔ **不做按日期自动升级**。自动跳意味着某天她打开 App 发现一切都变了，
而没有任何人跟她说过。家长区新增年级设置项，家长改。

### 6.3 ⭐ 升年级是仪式，不是断崖

改 `grade` 会**一次性触发三件事**：换三只新宠物（`ensurePets` 已会自动建）、
内容范围整体前移、二升三还要再叠一个「声音没了」。

必须有一个明确的过场：

- 「你已经是三年级的大孩子啦」
- 上一批伙伴**去了哪里**要说清楚（→ 我的伙伴页的回忆），不能凭空消失
- 二升三额外加一句「题目可以自己读了」——把「失去」讲成「长大」

❌ 绝不能让 App 无声无息地换掉一切。

## 7. 摸底跨年级下探

年级解决「从哪开始」，摸底解决「实际在哪」。三年级孩子进来，
她的真实水平可能在二年级下，也可能超前——**这才是「从三年级开始用」的真正需求**。

`domain/assessment/placement.ts`：

- `PLACEMENT_PROBES` 从硬编码的 7 个数学知识点 →
  `Record<Subject, Record<GradeLevel, readonly string[]>>`
- ⭐ **允许跨年级下探**：现在是「连错 2 题就停，第一个错的当起点」。
  改成阶梯——从档案年级的探测序列开始，连错 2 题则**换到下一个低年级的序列继续**，
  最多下探 1~2 个年级。
- ⚠️ 播不播语音按**孩子几年级**判，不按**题目属于几年级**。
  三年级孩子下探到二年级的题，那些题有语音包——按题目年级判会出现
  「做着做着突然开始说话」，比全程静音更怪。

## 8. 开放题不进 `attempts`

阅读理解、作文这类**没有客观判据**的题，由家长手录，做成**浏览页**，
与拼音乐园 / 识字 300 / 古诗 60 同类。

```
✅ 可看、可做、随时走
❌ 不出对错判定、不落 attempts、不记 mastery、不给积分、不影响宠物经验
```

**为什么不做家长批改**：整个数据模型（掌握度 EMA、SM-2、误区统计）都建立在
「这题对没对」上。引入「待批改」会让 `Attempt` 多一个可变状态，
而 attempts 是 append-only 的。

更重要的是它撞 CLAUDE.md 那条既有红线：**没有客观判据时，记录下来的是
「她做过什么」而不是「她会什么」，会让家长误读。**

**⭐ 实现时才发现的约束：动词挑物品。**

方案里以为骨架就是「句式 × 数值 × 词表」自由组合，实际不是——
句式一旦成了数据，动词就会和物品自由配对，撞出「**吃掉了 3 颗星星**」
「送走了 2 朵向日葵」这种不成话的题干。

因此 `Countable` 加了 `kind`（`edible` / `creature` / `object`），
句式用 `thingKinds` 声明它要什么类，生成器**先挑说法、再按说法挑物品**——
顺序反过来就挡不住。这个机制现在只服务「吃掉了」一处，
但二年级的应用题（买东西、分东西、几人平分）必然会大量用到。

**⚠️ 加句式的性价比不在句式本身，在语音片段。**

数字（`num()`）和物品（`clipKey`）的片段是现成的，换多少次都免费；
但每个新连接词都是一条 mp3。所以最划算的加法是
**保持骨架、只换那个动词**——复用已有的「原来有」「个」「还剩几个」，
只新增一个动词片段，就多出一种完整的说法。

这轮 9 个句式里：
- 4 个复用现有片段（含拿 M3 的「合起来是几」当加法的另一种问法），**零成本**
- 2 个各加一条片段（`phrase.thenCame` 又来了 · `phrase.ateUp` 吃掉了）
- 其余 3 个是原有句式

**为什么不给 compare 加「下面比上面少几个」**：那要求孩子先转换视角，
是另一种思维负担，而现有干扰项是按「多几个」设计的。
换句话说得连干扰项策略一起改，不属于「换个说法」。

**测试改法值得记一笔**：原来的「story 开关」测试写死了正则
（`^一共有几个.+？$`），加句式会让它红。改成断言 story 开关的**真正含义**——
M4 题干不出现数字（条件在图里）、M9 题干恰有两个数字（条件在话里）。
这样以后加说法不会误伤。

**怎么听**：`npm run story:check` 生成试听页。M4/M9 的 order 排在数学最后，
正常答题要把 M1~M8 都推过去才碰得到——想听一句新说法得先做上百道题。

⚠️ **试听页的播放必须复用 `platform/speechClips.ts` 的裁静音**，
这一页第一版自己写了一套播放逻辑、没裁静音，于是每两个片段之间凭空多出 1.2 秒，

#### ⭐ 「几个几」：乘法与除法共用同一幅图

| 问什么 | 是什么 | 答案 |
|---|---|---|
| 一共有几个 | 乘法 | 12 |
| 哪个算式说的是这幅图 | 乘加互换 | `3 × 4` |
| 平均分成 3 份，每份几个 | 平均分 | 4 |
| 4 个分一组，能分几组 | 包含除 | 3 |

图一样正是要点——**除法不该在两个月后作为一件全新的事情出现**。
`equalGroups.test.ts` 有一条专门锁它：同种子同参数下 `share` 与 `groupCount`
的配图完全相同，只有答案不同。

**每组画一个虚线框**，而不是像 `storyGroups` 那样只靠间距分开：
「几个几」的全部意思就在「组」这个概念上，摆成一堆散的这道题就退化成数数题，
而那是 M1 的内容——孩子实测嫌题目幼稚。

⛔ **绝不拿交换后的写法当干扰项。** 数学上 `4 × 3` 与 `3 × 4` 都对，

这是所有题里最伤人的一种错。干扰项一律在「数错了」和「用错了运算」上做。

#### ⭐ 二年级的文字应用题为什么另起一个生成器

`wordProblem.ts` 与 `storyProblem.ts` 分开，**不是因为年级**（§4.4 明说年级
不是算法属性），是因为两种题的形态不同：

| | `storyProblem`（一年级） | `wordProblem`（二年级） |
|---|---|---|
| 配图 | emoji 分组图 | ❌ 不配图 |
| 步数 | 一步 | 含两步 |
| 数值 | ≤10 | 到 99 |

⚠️ **不配图是被数值逼出来的**：「22 个小朋友坐船」摆 22 个 emoji 在 iPad 上
是一片糊，而教材里这类题本来就是纯文字。题干靠朗读——这也正是
「语音包做到二年级为止」这条线划得对的地方：二年级的应用题她还读不了。

⭐ `atLeast`（至少要几条船）是这批里唯一真正新的东西：**答案是商 + 1**。
因此题目**恒除不尽**——除得尽的话商就是答案，这道题的全部难点就没了，
`remainder_ignored` 那个干扰项也会等于正确答案被剔除。

`twoStepLess` / `twoStepMore` 分成两个 op 而不是共用一个：句式看着只差一个
动词（吃掉了 / 又来了），但第二步的运算不同、答案也不同，
共用会让生成器按加法算、题干却在说减法。

#### ⭐ 实现时才发现的五件事

**① 标签清单要等生成器写完才算定稿。**
按教材单元名推出来的 `carry_chain` / `borrow_chain` 在二年级**没有落点**：
100 以内加减法结果不超过 100，竖式最多进位一次，孩子「个位进了位、十位忘了
加那个 1」就是 `no_carry`。真正的连续进位（187 + 256）要到三年级。
两个标签已删。**判据得是「这道题的选项长什么样」，不是单元名。**

**② `num()` 只覆盖 0~20，是二年级的隐形地基。**
超出会逐位拼读——「35」念成「三 五」。扩到 9999 时中文数字的三个坑全都要处理：
零占位（3005 是三千零五，漏了零就和 305 一样）、一十（110 是一百一十，
而单独的 10 念「十」）、整十不带尾。
位值片段刻意叫 `num.hundred` 而不是 `num.100`，因为它念的是「百」不是「一百」——
叫后者会让人想当然填成 `100`，而**错法只有听才发现**。

**③ 干扰项算出负数会被静默剔除，这道题就诊断不出东西了。**
`buildNumericOptions` 会过滤负数，`buildTextOptions` 连补位都没有。
被测试抓出来三处：`12 - (8 - 7)` 无视括号一路减成 −3；同级运算 `a - b + c`
的「先算后面」需要 `a ≥ b+c`；商与余数相等时（`2 余 2`）对调后就是正确答案。
**每加一个干扰项都要问一句：它在参数的边界上还成立吗。**

**④ 混合运算两种排法都得出。**
`2 + 3 × 4` 的错法是从左往右；`3 × 4 + 2` 从左往右**反而是对的**，
错法是跳过去先算加。只出前一种，她会把规则记成「先算右边」，
碰到后一种照样错。

**⑤ 考写法的题不能朗读题干。**
「3005 读作什么」念出来就是答案。只念提示语——这和拼音标调题
`phrase.toneMark1`「这个音节读第一声」是同一条理由。

#### ⚠️ 题型多样目前是「弱多样」

纯计算题的两条模板靠 `readItemType` 的 `as` 参数在
`input_number` / `choice_text` 之间轮换。只放开这两者是因为它们**数据结构
完全相同**（四个选项 + 一个答案字符串），差别只在 UI 怎么渲染。

对孩子这是能感觉到的两种题（敲数字键盘 vs 点四个选项，后者还能用排除法），
但**比不上真正的拖拽与配对**。`matchPairs` 是「分与合」专用的
（每对之和等于 total），套不到乘法上；乘法口诀的连线题需要新的 `visual`
类型和配套组件——那和图形类 SVG 是同一批工作。

#### ⭐ 模板契约靠「真跑一遍」守，不靠白名单

`itemTemplates.test.ts` 原本有一条「声明了 `choice_text` 就必须传 `as` 参数」，
靠一张「哪些生成器默认产 `choice_text`」的白名单判断——**白名单立刻就过时了**
（`comparison` 漏在外面）。

改成把每条二年级模板的三档**各真跑一遍**，比对声明与实际产出。
这条断言强得多：对不符的任何原因都成立，还顺带验证了每条模板的参数配得对、
真的出得了题（出题抛错在这里就会暴露）。

#### 下一步做什么（按性价比排）

**只剩 SVG 那一块了。** 建议顺序（按「画起来有多难」排，先易后难）：

1. **角**（4 个知识点）—— 两条线段加一个顶点，最简单，且 `angle_side_length`
   这个误区靠「边长不同、开口相同」两张图就能考出来
2. **尺子与线段**（3 个）—— 一条带刻度的横线。⭐ `ruler_start_wrong` 要求
   物体能摆在非 0 刻度处，画的时候就得把「起点」做成参数
3. **轴对称 / 平移 / 旋转**（4 个）—— 需要一套能翻转和平移的简单图形
4. **统计表与条形图**（2 个）—— 柱子好画，但要考虑坐标轴标注怎么让不识字的
   孩子读懂
5. **三视图**（2 个）—— 最难，要画同一堆积木从三个方向看到的样子

做完之后：**宠物 G2 三只 + 语音封版**，然后才轮到 8.7 的三件顺带的。

⚠️ 动手前先看 `components/shape/` 现有的画法（`MathShape` / `ShapeScene` /
`ClockFace`）。一年级的图形题已经把「手绘 SVG、坐标由 domain 算好、组件只负责画」
这套模式跑通了，二年级照着来即可——**坐标必须留在生成器里算**，
摆放位置是题目内容的一部分，要能被固定种子复现。

⚠️ **新句式还没听过。** 跑 `npm run story:check` 逐条试听二年级那 11 条
应用题句式——尤其 `phrase.boxesOf`（孤立的「盒」）这种单字，
以及「小明有…小红比他多…」这句人名开头的，读飘了要进 `TAIL_FIX_KEYS`。
