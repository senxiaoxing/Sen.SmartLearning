# 技术方案

> 目标形态：**PWA（渐进式 Web 应用）**，iPad / iPhone「添加到主屏幕」后全屏运行
> 开发环境：**Windows**（无需 Mac）｜ 成本：**¥0** ｜ 数据：**纯本地，不上云**
> 开发方式：**全程 AI 辅助编码**

---

## 0. 约束驱动的选型逻辑

先把决定选型的四个硬约束列清楚，后面每个技术决策都可以追溯到这里：

| # | 约束 | 推导出的结论 |
|---|---|---|
| C1 | 只有 Windows，没有 Mac | iOS 原生 App **不可行**（Xcode 仅 macOS）→ 必须走 Web/PWA |
| C2 | 不买开发者账号（$99） | 排除 TestFlight / 上架 → PWA「添加到主屏幕」是唯一路径 |
| C3 | 要在 iPad 上漂亮且流畅 | 动画只用 GPU 合成属性；避免重量级 Web 框架 |
| C4 | 全程 AI 写代码 | 选 **AI 训练数据最多、环境最不易踩坑**的栈；纯函数优先，便于验证 |

> **为什么不是 Flutter**：Flutter Web 的 CanvasKit 首屏要加载 1.5MB+ WASM，
> iOS Safari 上滚动与触摸手感失真，Rive/Lottie 在 Flutter Web 端支持也弱。
> 若将来买 Mac 做原生包，用 **Capacitor** 包壳即可，代码几乎不改。

## 1. 技术栈

```
React 18 + TypeScript 5 + Vite 5
├─ 样式        Tailwind CSS 3
├─ 动效        Framer Motion（交互动效） + lottie-web（复杂动画）
├─ 状态        Zustand（轻量，无 Provider 地狱）
├─ 路由        React Router 6
├─ 存储        Dexie.js 4（IndexedDB）
├─ 音频        Howler.js（音效/BGM） + Web Speech API（TTS）
├─ PWA         vite-plugin-pwa（Workbox）
├─ 测试        Vitest（纯函数逻辑必测）
└─ 部署        Cloudflare Pages（免费，自动 HTTPS）
```

**明确不引入**：Redux、Next.js、任何 UI 组件库（MUI/AntD——儿童界面全定制，组件库只会碍事）、
任何需要服务端的依赖。

### 为什么是这几个

| 选择 | 理由 |
|---|---|
| **Vite** | 冷启动秒级，`--host` 一开 iPad 直连热更新，改一行抬头就能看到 |
| **Zustand** | 3 行定义一个 store，AI 生成出错率极低；Redux 样板代码会拖慢 AI 协作 |
| **Tailwind** | AI 写样式的一致性远高于手写 CSS；无需在文件间跳转 |
| **Framer Motion** | 声明式动画，默认走 transform/opacity，天然满足 C3 |
| **Dexie** | IndexedDB 原生 API 极其难用，Dexie 的查询语法接近 SQL，AI 写得对 |
| **Howler** | 自动处理 iOS 音频解锁、音频精灵图、并发播放 |

## 2. 架构分层

```
┌─────────────────────────────────────────────┐
│  Presentation  React 组件 / 页面 / 动画      │  ← 只负责渲染和交互
├─────────────────────────────────────────────┤
│  Application   Zustand Stores / Hooks       │  ← 编排，连接 UI 与领域
├─────────────────────────────────────────────┤
│  Domain        ⭐ 纯函数，零依赖，100% 可测   │
│   scheduler  mastery  generators  economy   │
│   petLogic   achievements  assessment       │
├─────────────────────────────────────────────┤
│  Data          Dexie Repositories           │  ← 唯一接触数据库的层
├─────────────────────────────────────────────┤
│  Platform      audio / tts / storage / pwa  │  ← 浏览器 API 封装
└─────────────────────────────────────────────┘
```

### ⭐ Domain 层是纯函数——这是 AI 协作的关键设计

所有核心逻辑（出题、掌握度计算、题目生成、积分、宠物状态）写成**无副作用的纯函数**：

```ts
// ✅ 这样写：AI 容易写对，也容易验证
export function updateMastery(
  current: Mastery,
  attempt: Attempt,
  kp: KnowledgePoint
): Mastery { /* 只做计算，不碰数据库、不碰 UI */ }

// ❌ 不要这样写：AI 容易写错，且无法单测
export async function handleAnswer(itemId, selected) {
  const m = await db.mastery.get(...)   // 数据库
  m.score = ...                          // 计算
  await db.mastery.put(m)                // 数据库
  setState(...)                          // UI
  playSound('correct')                   // 副作用
}
```

**收益**：出题逻辑写错了，跑一个 Vitest 就知道，不用把 App 装到 iPad 上点半天。
对"全程 AI 写代码"而言，这是最重要的一条架构约定。

### 4.1 出题调度器 `selectNextItems`

会话开始时一次性选出整段题目（便于资源预加载），而非逐题决策。

```ts
interface ScheduleInput {
  profileId: string
  mode: 'daily' | 'free' | 'review' | 'remedial'
  subject?: Subject
  count: number                    // 一段的题量，默认 25
  masteryMap: Map<string, Mastery>
  knowledgePoints: KnowledgePoint[]
  now: string
}

export function selectNextItems(input: ScheduleInput): ScheduledItem[]
```

**配比策略**

| 比例 | 来源 | 目的 |
|---|---|---|
| **30%** | `state === 'review'` 且 `dueAt <= now` | 间隔重复，防遗忘 |
| **50%** | `state === 'learning'` 的当前知识点 | 主推进 |
| **20%** | 已 `mastered` 的低难度题 | ⭐ 保持成就感，防挫败 |

**关键规则**

1. **难度自适应**
   `masteryScore > 0.85` → 难度 +1；`< 0.60` → 难度 -1，且**回退到前置知识点**
2. **关键节点保护**
   若 `M5.*` 大面积出错（正确率 < 50%），无条件插入 `M3.3`（10的分与合）专项
3. **诊断性补救** ⭐
   `misconceptionCounts['bd_confusion'] >= 3` → 自动插入 `P7.1`（b/d 辨析）专项
4. **开局与收尾**
   首题必须是已掌握的简单题（暖场），末题必须是能答对的题（好心情结束）
5. **防连续挫败**
   连续答错 3 题 → 强制插入 2 道简单题，并让宠物出来鼓励
6. **题目去重**
   同一会话内不出现重复 `itemId`；数学生成题按参数签名去重

```ts
// 难度调节
function adjustDifficulty(m: Mastery): { kpId: string; difficulty: 1|2|3 } {
  if (m.masteryScore > 0.85 && m.currentDifficulty < 3)
    return { kpId: m.kpId, difficulty: (m.currentDifficulty + 1) as 1|2|3 }
  if (m.masteryScore < 0.60) {
    const weakest = findWeakestPrerequisite(m.kpId)   // 回退到前置
    if (weakest) return { kpId: weakest, difficulty: 1 }
    return { kpId: m.kpId, difficulty: 1 }
  }
  return { kpId: m.kpId, difficulty: m.currentDifficulty }
}
```

### 4.2 数学题目生成器

**契约**（所有生成器统一签名，AI 照着写不会跑偏）：

```ts
export interface GeneratorContext {
  difficulty: 1 | 2 | 3
  params: Record<string, unknown>
  rng: () => number              // ⭐ 注入随机源，便于测试时固定种子
  exclude?: string[]             // 已出过的签名
}

export interface GeneratedItem {
  signature: string              // 'M5.2-gen#9+5' 用于去重与快照
  kpId: string
  type: ItemType
  difficulty: 1 | 2 | 3
  stem: { text: string; ttsText: string }
  options: ItemOption[]
  answer: string
}

export type Generator = (ctx: GeneratorContext) => GeneratedItem
```

**示例：进位加法**

```ts
// domain/generators/addWithCarry.ts
export const addWithCarry: Generator = ({ difficulty, params, rng }) => {
  const a = params.addendA as number                       // 9
  const [lo, hi] = params.addendBRange as [number, number]
  const b = lo + Math.floor(rng() * (hi - lo + 1))
  const answer = a + b

  const options = buildDistractors(answer, [
    { tag: 'no_carry',     value: answer - 1 },   // 忘记进位
    { tag: 'carry_lost',   value: 10 },           // 凑十后忘记加剩余
    { tag: 'sub_instead',  value: Math.abs(a - b) },
  ], rng)

  return {
    signature: `M5.2-gen#${a}+${b}`,
    kpId: 'M5.2',
    type: 'input_number',
    difficulty,
    stem: { text: `${a} + ${b} = ?`, ttsText: `${a} 加 ${b} 等于几` },
    options,
    answer: String(answer),
  }
}
```

**干扰项铁律** ⭐

```
❌ 随机数干扰项 —— 提供零信息
✅ 认知误区干扰项 —— 孩子选了哪个，就知道她卡在哪一步
```

`9 + 5 = ?` 的选项必须是 `14`(正确) / `13`(no_carry) / `10`(carry_lost) / `4`(sub_instead)。
选 `13` 说明凑十过程丢了 1，选 `10` 说明凑十后忘记加——**两种错误的补救路径完全不同**。
这是整个系统"智慧"的来源，也是与普通题库 App 的根本差别。

`distractors.ts` 还要保证：干扰项互不重复、不等于正确答案、数值合理（不出现负数）、
选项顺序随机但正确答案不总在同一位置。

### 4.3 掌握度引擎

```ts
// domain/mastery/updateMastery.ts —— 纯函数
export function updateMastery(
  current: Mastery,
  attempt: Attempt,
  kp: KnowledgePoint
): Mastery {
  const ALPHA = 0.3
  const target = attempt.isCorrect ? 1 : 0
  const weight = attempt.isCorrect
    ? 0.7 + attempt.difficulty * 0.15
    : 1.3 - attempt.difficulty * 0.15

  const masteryScore = clamp(
    current.masteryScore + ALPHA * weight * (target - current.masteryScore), 0, 1)

  const consecutiveCorrect = attempt.isCorrect ? current.consecutiveCorrect + 1 : 0

  const misconceptionCounts = { ...current.misconceptionCounts }
  if (attempt.misconceptionTag) {
    misconceptionCounts[attempt.misconceptionTag] =
      (misconceptionCounts[attempt.misconceptionTag] ?? 0) + 1
  }

  const next = { ...current, masteryScore, consecutiveCorrect, misconceptionCounts,
                 totalAttempts: current.totalAttempts + 1,
                 correctAttempts: current.correctAttempts + (attempt.isCorrect ? 1 : 0) }

  return applyStateMachine(applySpacedRepetition(next, attempt), kp)
}
```

详细公式与状态跃迁表见 **[02-数据库Schema.md](./02-数据库Schema.md) §3.8**。

### 4.4 音频系统（PWA 最容易踩坑的地方）

```ts
// platform/audio.ts
class AudioManager {
  private unlocked = false

  /** ⚠️ iOS 必须在用户手势中首次调用，否则后续所有音频静默失败 */
  async unlock(): Promise<void> {
    if (this.unlocked) return
    await Howler.ctx?.resume()
    new Howl({ src: [silentMp3], volume: 0 }).play()   // 播一段静音解锁
    this.unlocked = true
  }

  playSfx(key: SfxKey): void { /* 音频精灵图，零延迟 */ }
  playBgm(key: BgmKey): void { /* 循环 + 淡入淡出 */ }
}
```

**iOS 音频三条铁律**

1. **首屏必须有「开始学习」按钮**，在它的 click 里调 `unlock()`。这是 iOS 的硬性要求，绕不过去。
2. **所有音效打包成 audio sprite**（单文件 + 时间偏移），避免几十个小文件的加载延迟。
3. **TTS 结果缓存**：Web Speech API 每次都实时合成，拼音 420 个音节高频复用，
   首次合成后缓存到 IndexedDB，之后离线可用且零延迟。

```ts
// platform/tts.ts
export async function speak(text: string, lang: 'zh-CN' | 'en-US'): Promise<void> {
  const cached = await getCachedAudio(text, lang)
  if (cached) return playBuffer(cached)

  const u = new SpeechSynthesisUtterance(text)
  u.lang = lang
  u.rate = settings.ttsRate          // 儿童建议 0.85
  u.voice = pickVoice(lang)          // 优先选择质量更高的系统音色
  speechSynthesis.speak(u)
}
```

> ⚠️ **Haptic 触觉反馈在 iOS Safari 不可用**（不支持 Vibration API）。
> `platform/haptics.ts` 做成空实现 + 音效降级。**用好音效能弥补大部分手感损失**——
> 点击、答对、答错、金币掉落各配一个音效，这是"高级感"最廉价的来源。

### 4.6 家长门禁（Parent Gate）

家长区（报告、备份、设置）必须有门禁，否则孩子会自己改时长限制。

```tsx
// 长按右上角 3 秒 → 弹出算术题（一年级做不出的难度）
// 例："37 + 46 = ?" 或 "按顺序点击：4 → 9 → 2"
// 这是 Apple Kids Category 的标准做法，成本极低且有效
```

**⚠️ 出题逻辑住在 `domain/parent/parentChallenge.ts`，不要挪回组件里**

它原先内联在 `ParentGate.tsx`，写成拒绝采样：

```ts
let a = pick()                                  // 23..79
let b = pick()
while ((a % 10) + (b % 10) < 10) b = pick()     // ⚠️ 只重抽 b
```

`a` 的个位为 0 时（30/40/50/60/70，约 **9%** 的概率）需要 `b % 10 >= 10`，
**永远不成立** → while 退不出 → 主线程卡死 → 浏览器弹「页面无响应」，
家长区再也进不去。2026-08-19 由家长实测报出。

三条教训，值得推广到别处：

1. **能直接构造就别拒绝采样。** 现在的写法是先定 `a` 的个位（1~9），
   再让 `b` 的个位从「刚好凑满 10」起跳——进位由构造保证，结构上不可能不终止。
2. **概率性的 bug 最难查。** 九次里有八次是好的，重开一次就「好了」，
   看起来像浏览器毛病而不像代码问题。它因此潜伏了很久。
3. **所以它必须能被单测。** 搬进 `domain/` 才能注入固定随机源，
   把「一定会返回」当成一条断言写下来（`parentChallenge.test.ts` 第一组用例）。

### 4.7 语文三块：教而不练（2026-08 新增）

拼音乐园 `/pinyin` · 识字 100 `/hanzi` · 古诗 20 `/poems` `/poems/:id`。
与字母乐园 `/letters` 是**同一类页面**，三条体验约束完全一致：

```
1. 全部可点     —— 没学到的也能翻能听。这是「教」不是「练」，
                   任何锁都会挡住她玩，而玩本身就是这几页存在的理由
2. 没有对错判定 —— 乱点、反复点、只挑喜欢的点，都不该有任何评价
3. 随时可走     —— 顶部返回一直在
```

#### ⚠️ 它们**不进**答题系统

不产生 `attempts`、不更新 `mastery`、不给积分、不影响宠物经验。
识字与古诗**也不在那 112 个知识点里**（见 design/01 §附录）——
下次不要为它们建知识点或写生成器，那会把「随便翻翻」变成又一份作业。

数据流因此极简：seed 常量 → 组件直接渲染，零仓储、零 store、零数据库改动。

#### 进度显示：有 mastery 才显示

| 页面 | 进度 | 为什么 |
|---|---|---|
| 拼音乐园 | ✅ 已学的**组**带高亮圈 | 拼音有题库，`P1~P6` 的 mastery 是真实作答产出的 |
| 识字 / 古诗 | ❌ 无 | 没有题库就没有「认识了没有」的客观判据 |

⭐ **刻意不做识字的收藏星标与「今日 N 字」**（参考应用有）。那需要新建用户数据表，
连带处理导出/导入与 `schemaVersion` 迁移（design/02）；更根本的问题是：
在无法自动判定「认识了没有」之前，星标记录的是**她点过什么**而不是**她认识什么**，
反而会让家长误读。

> 想加的正确顺序：先有识字题库（产出 mastery）→ 再让这面墙读 mastery，
> 与拼音乐园的高亮圈完全一致。

#### 入口

首页底部 `PlayEntries.tsx`，五个入口顺序**写死**（语文三块 → 字母 → 讲解）。
孩子记的是「古诗在第三个」这种位置记忆，入口自己动来动去比多点一次严重得多——
与 `SUBJECT_ORDER` 写死是同一个道理。

⚠️ 进这几页前必须 `unlockAllAudio()`：全部内容都是听的，而 iOS 只认手势那一瞬间的调用栈。

## 5. UI/UX 硬约束

### 5.1 一年级孩子不识字 —— 这条反向决定整个界面

| **无文字输入** | 除了给宠物起名，全程无键盘（数字用大号自绘小键盘） |

### 5.2 视觉与动效

```
配色    高饱和但低亮度对比，避免纯白背景（护眼）
        主色圆润渐变，深浅色模式都要适配
字体    大字号（正文 ≥ 20px，题干 ≥ 32px），圆体优先
圆角    统一 16~24px，无锐角
反馈    每次交互必有：视觉 + 音效 双反馈
答对    Lottie 星星爆开 + 上扬音效 + 积分飞入计数器
答错    ⭐ 温和：轻微摇动 + 柔和提示音，绝不用红叉/刺耳音
        文案："再看看～" 而不是 "错误"
```

### 5.3 性能规范（保证 iPad 流畅）

```
✅ 动画只用 transform / opacity（GPU 合成层）
❌ 禁止动画 width/height/top/left/margin（触发 layout，必掉帧）
✅ 长列表（图鉴 112 张）用虚拟滚动或分页
✅ 图片用 WebP，尺寸按 @2x 出，超过 200KB 必须压缩
✅ 会话开始前预加载本段全部题目资源（避免答题中途卡顿）
✅ Lottie 动画控制在 200KB 以内，复杂动画降级为序列帧
❌ 禁止在渲染路径中做 IndexedDB 查询（预取到 store）
```

**验收标准**：iPad 上答题交互 **60fps 无掉帧**，题目切换 **< 100ms**，冷启动 **< 2s**。

## 8. AI 协作规范 ⭐

因为全程 AI 编码，这一节直接决定项目能否走远。**建议把本节内容单独写入项目根目录的 `CLAUDE.md`。**

### 8.1 三条铁律

```
1. 类型先行
   动手写任何功能前，先在 domain/types.ts 定义好类型。
   类型是 AI 与你之间的契约，没有契约 AI 每次生成的结构都会漂。

2. Domain 层必须是纯函数
   禁止在 domain/ 下 import React、Dexie 或任何浏览器 API。
   纯函数 AI 写得对、你验得快、单测跑得动。

3. 一次只做一件事
   一个对话只实现一个模块。不要说"帮我把答题功能做完"，
   要说"实现 domain/generators/addWithCarry.ts，签名见 §4.2"。

4. 单文件自足
   每个文件带 @file + @layer 头注释块；核心逻辑写完整 JSDoc（含 @example）。
   目标：AI 打开任意单个文件就能理解全部上下文，不必跳转拼凑。
   完整规范见项目根目录 CLAUDE.md 的「目录与文件规范」「注释与 JSDoc 规范」两节。
```

### 8.2 给 AI 下任务的模板

```markdown
## 任务
实现 src/domain/generators/addWithCarry.ts

## 契约
- 输入输出类型见 src/domain/types.ts 的 Generator / GeneratorContext
- 配置见 design/02-数据库Schema.md §3.6 的 M5.2-gen 示例

## 要求
1. 纯函数，不 import React/Dexie/浏览器 API
2. 随机数必须用 ctx.rng()，不能用 Math.random()（要可测试）
3. 干扰项必须按认知误区生成，见 design/03-技术方案.md §4.2 干扰项铁律
4. 文件头写 @file + @layer 注释块；导出函数写完整 JSDoc，
   必须含 @example 列出各干扰项对应的认知误区，格式见 CLAUDE.md「注释与 JSDoc 规范」
5. 文件不超过 150 行；只有一个主导出；不创建 index.ts
6. 同时生成同目录的 addWithCarry.test.ts，至少覆盖：
   - 固定种子下输出稳定
   - 干扰项不重复、不等于答案、无负数
   - 三档难度的数值范围正确

## 禁止
- 不要修改其他文件
- 不要引入新依赖
- 不要在 docs/ 下创建文件
```

### 8.3 每个模块完成后的验证

```powershell
npm run typecheck     # tsc --noEmit
npm run test          # vitest run
npm run lint
```

**必须有单测的模块**（逻辑错了在 iPad 上看不出来）：

- `domain/generators/*` —— 干扰项策略、数值范围、去重
- `domain/mastery/*` —— 掌握度公式、状态跃迁、SM-2 间隔
- `domain/scheduler/*` —— 配比、难度调节、防挫败规则
- `data/backup/*` —— ⭐ **导出→导入往返一致性，这个必须测**

```ts
// 备份往返测试 —— 数据丢失是最不可接受的故障
it('导出后导入应完全还原', async () => {
  const before = await snapshotAllUserTables(pid)
  const backup = await exportBackup(pid)
  await clearAllUserTables()
  await importBackup(backup)
  const after = await snapshotAllUserTables(pid)
  expect(after).toEqual(before)
})
```

### 8.4 容易被 AI 写错的地方（重点 review）

| 高风险点 | 检查什么 |
|---|---|
| 时间处理 | `localDate` 是否用**本地时区**计算；`createdAt` 是否为 UTC |
| ID 生成 | 用户数据是否用 `crypto.randomUUID()`，**有无自增 ID** |
| 干扰项 | 是否退化成随机数；有无 `misconceptionTag` |
| iOS 音频 | 是否在用户手势内解锁；有无未解锁就播放的路径 |
| 动画属性 | 有无动画 `width/height/top/left`（必掉帧） |
| 宠物逻辑 | 有无死亡/掉阶/惩罚逻辑（产品红线） |
| 积分 | 余额是否从 ledger 推导，有无独立可变余额字段 |
| 备份 | 是否包含 `schemaVersion`；是否误导出了静态表 |

## 9. 风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| ⭐ **孩子玩两天就腻** | 项目失去意义 | **最高优先级**：尽早出可玩版本上机验证，不要等功能完整 |
| 数据丢失（清缓存/换设备） | 进度归零，孩子受挫 | 导出/导入 MVP 必做；每周提醒备份；里程碑自动提示 |
| 未「添加到主屏幕」 | Safari 7 天清数据 | 首次访问强引导；家长区检测并提示 |
| iOS 音频未解锁 | 全程无声，App 报废 | 首屏「开始学习」按钮强制解锁；加自检提示 |
| TTS 音色差/不稳定 | 拼音发音不准误导孩子 | 拼音音节改用**预录/预生成音频**，不依赖运行时 TTS |
| 图片资源过大 | 加载慢、卡顿 | WebP + 压缩流水线；单图 < 200KB |
| 内容量不足 | 几天刷完，重复 | 数学靠生成器（无限）；拼音英语先保证深度 |
| AI 生成代码结构漂移 | 越写越乱 | 类型先行；纯函数分层；每模块单测 |

> **最大的风险不是技术做不出来，而是做完六周发现她玩两天就腻了。**
> 因此第一优先级永远是：**尽快让她玩到，观察真实反应**。她的表情比任何需求文档都准。
