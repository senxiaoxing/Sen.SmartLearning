# 音频方案

> 音效 + 语音。**运行时零网络**：所有音频随包发布，离线可用。
> 相关代码：`platform/audio.ts` · `platform/speech.ts` · `domain/speech.ts` · `data/seed/voiceManifest.ts`

---

## 0. 两个独立的问题

| | 音效（SFX） | 语音（Voice） |
|---|---|---|
| 是什么 | 点击、答对、答错、升级的提示音 | 题干、反馈语、讲解的朗读 |
| 之前 | **完全没有** | Web Speech 实时合成 |
| 问题 | 每次交互只有视觉反馈，缺一半 | **音色差**，且拼音必须预录 |
| 现在 | 6 个脚本合成的 WAV | 预生成 mp3 片段拼接，TTS 兜底 |

---

## 1. 音效

### 1.1 为什么是脚本合成而不是找素材

免费音效库的授权条款五花八门，而「柔和、不刺耳、适合一年级」这个要求很难靠搜索命中。
这几个音本质上就是几条正弦波加包络，自己算反而更可控——
想让答错音再柔一点，改一个数字重跑 `npm run sfx` 就行。

输出 WAV 而非 MP3：六个音总共约 100KB，省下 MP3 编码器的复杂度，iOS Safari 对 WAV 支持良好。

> **要换成真实音效素材时**：把同名文件丢进 `public/audio/sfx/` 覆盖即可，代码一行不用改。

### 1.2 六个音

| key | 用途 | 设计要点 |
|---|---|---|
| `tap` | 所有 `BigButton` 点击 | 极短极轻，只确认「点到了」，不能有存在感 |
| `place` | 拖拽卡片落进槽 | 闷一点的短音，确认「吸住了」 |
| `correct` | 答对 | 上行大三度，明亮但不夸张 |
| `wrong` | 答错 | ⭐ **下行小三度 + 40ms 慢起音**，音量压到六成 |
| `complete` | 一轮完成 | 两个音收尾，比升级克制 |
| `levelUp` | 宠物升级/变身 | C 大调琶音，全 App 最「大」的音 |

> ⭐ **`wrong` 是产品红线所在**（CLAUDE.md「答错反馈要温和」）。
> 慢起音去掉了「咔」的攻击感，听起来像一声轻轻的「嗯…」而不是警报；
> 音量刻意低于 `correct`——**答错的反馈不该比答对更响亮**，那是在放大挫败感。

### 1.3 接线位置

```
BigButton.onClick        → tap        全 App 的按钮都走它，一处接线全覆盖
usePlacement.place()     → place      拖与点两条通道都经过它
Feedback（进入反馈态）    → correct / wrong
SessionSummary（挂载）   → levelUp 有升级时 / complete 否则
```

⚠️ 选项按钮**不接** `tap`：它点下去几十毫秒后就是 `correct`/`wrong`，两个音会糊在一起。

## 2. 语音

### 2.1 为什么弃用实时 TTS

1. **音色差** —— Web Speech 在 Windows 上用的是老式 SAPI 音色，实际听感不能接受
2. **拼音必须预录** —— design/03 §9 风险清单早就写明：
   拼音音节靠运行时 TTS 会发音不准，**误导孩子**，这是内容正确性问题不是体验问题
3. **不确定性** —— 同一句话在不同设备、不同系统版本上音色不同，且随系统更新变化

### 2.2 核心思路：题干是拼出来的，语音也拼出来

数学题运行时生成，题面无穷无尽，不可能为每道题预录一条音频。
但它们都由极小的词汇表拼成：**0~20 的数字 + 几十个固定短语**。

于是把一句话表示成**片段 key 的数组**：

```ts
// 9 + 5 = ?
{ parts: ['num.9', 'op.plus', 'num.5', 'phrase.equalsWhat'],
  fallbackText: '9 加 5 等于几' }
```

无穷多的题目只需要**几十个音频文件**，而且发音完全稳定。

### 2.3 ⭐⭐ 必须裁静音 —— 否则一句话要念 7 秒

Edge TTS 的输出有**固定最小长度**。实测每个短片段都是 **1.78 秒**，
而其中真正的人声只有 0.24~0.64 秒，**尾部一律拖着约 1.2 秒静音**：

| 片段 | 文件时长 | 人声区间 | 尾部静音 |
|---|---|---|---|
| `num.5`（五） | 1.78s | 0.21–0.57s | 1.21s |
| `op.plus`（加） | 1.78s | 0.22–0.46s | 1.32s |
| `phrase.equalsWhat`（等于几） | 1.87s | 0.21–0.85s | 1.02s |

于是「9 加 5 等于几」按原样播放要 **7.3 秒**，其中 5.8 秒是死气——
孩子实测反馈「读得很慢」，根因就在这里。

**修法**：解码后按能量扫描定位人声区间，裁掉前后静音再播。同一句降到 **2.4 秒**。

```
裁剪前  ■□□□□ ■□□□□ ■□□□□ ■□□□□   7.3s（■人声 □静音）
裁剪后  ■ ■ ■ ■                      2.4s
```

⚠️ 裁剪保留前后各 30ms 余量：塞擦音（z c s）起音很轻，
卡着门限切会把字头削掉，听成另一个音。

### 2.4 播放走 Web Audio，不用 Howler

音效用 Howler（即发即忘，正合适），**语音必须用 Web Audio**：

1. 要裁静音——Howler 不做这件事
2. 要在音频时钟上**一次性排期**整句。边放边解码会在片段之间插进不确定的加载延迟，
   听感就是「一顿一顿的」
3. 原来用 Howler 按需加载，首次用到某片段时它还没加载完，
   而新的朗读会调 `stop()` 取消排队播放，于是**低频片段整个被吞掉**——
   孩子实测反馈「有的数字没读出来，比如 15」，正是这个原因。
   现在解锁时预热数字与运算词（约 27 个、300KB），播放时一定是就绪状态。

### 2.5 三条播放路径 —— ⭐ 绝不能通向静音

```
片段齐全   → 按顺序播放预生成 mp3      ← 目标状态：音色稳定、离线、零延迟
缺任一片段 → 整句降级为实时 TTS        ← 音色不一致，但听得见
无 TTS 支持 → 静默失败，但不抛错        ← 页面不能崩
```

孩子不识字，题干读不出来 = **这道题她做不了**。
宁可某一句音色不一致，也绝不能让她盯着一道读不出来的题。

> ⚠️ 缺片段时是**整句**走 TTS，不是「有的片段有的 TTS」。
> 混着播会得到「9 加（真人声）…（机器声）等于几」，比全程机器声更难听。

### 2.6 片段清单是唯一事实源

`data/seed/voiceManifest.ts` 同时被**生成脚本**和**运行时**读取。

如果脚本自己维护一份「要生成哪些音频」的列表，它迟早和代码实际用到的片段对不上：
多生成的是死文件，少生成的是**静音**。共用一份清单 +
`voiceManifest.test.ts` 校验「代码里用到的片段都在清单里」，这类漂移不可能发生。

### 2.7 生成

```powershell
npm run voices                                   # 只补缺失的、以及文本或参数变了的
npm run voices -- --force                        # 全部重生成
npm run voices -- --force=pinyin.                # 只重生成拼音（调音色/韵律后用）
npm run voices -- --voice-pinyin=zh-CN-XiaoyiNeural
npm run voices -- --voice-en=en-GB-MaisieNeural  # 换成英式童声
```

**构建期联网，运行时纯本地** —— 生成好的 mp3 随包发布，App 跑起来不碰网络。

### ⭐ 三套音色，按 key 前缀分

| key 前缀 | 音色 | 语速/音调 | 为什么 |
|---|---|---|---|
| `pinyin.*` | `zh-CN-XiaoxiaoNeural` | `-30%` / `+0%` | ⭐ 播音腔，**发音标准优先于亲切** |
| `en.*` | `en-US-AnaNeural` | `-15%` / `+5%` | 儿童声，与中文侧年龄接近 |
| 其余 | `zh-CN-XiaoyiNeural` | `-15%` / `+5%` | 少女声，题干与鼓励语 |

> ⭐ **中英文必须分音色。** 用中文音色念 `apple` 得到的是一个孩子听不懂、
> 也学不对的音——这与拼音「裸拼音会读错声调」是同一类问题，
> 而发音教错比没有声音严重得多。脚本按前缀切音色，
> 一个 worker 绑定一个音色（`setMetadata` 是连接级设置，中途换不了）。

### ⭐⭐ 拼音为什么单独一套：孤立单字的声调会读飘

人工复听（`npm run pinyin:check`）报回 18 个发音有问题的音节，
其中 **11 个是一声**（`pō mō kē hē wū āo ōu yē ēn wēn āng`），
另有三声的 `nǐ`。模式很清楚：**全都是孤立的单个汉字**。

根因是中文 TTS 念孤立单字时缺少语境，韵律模型按「一整句」处理，
句末天然带降调倾向，把一声的高平调（55）拖成下降；
三声在快语速下则被压成「半三声」，孩子听到的不是课本上那个音。

两条对策，都只作用于 `pinyin.*`：

1. **换标准播音音色** —— 少女声念题干很好，念孤立单字不够稳。
   播音腔在别处是缺点，在「教这个音该怎么念」上恰恰是优点。
2. **`-30%` 语速 + `+0%` 音调** —— 慢让声调走完；⚠️ 而音高偏移是可疑因素：
   中文声调本就是**相对音高的变化**，TTS 的整体升调并非简单平移，
   一声（本就在音域高处）被抬高后容易撞顶变形。
   别处的 `+5%` 只影响亲切感，这里影响对错。

> ⚠️ 台账 `.spoken-text.json` 现在同时记录**生成参数指纹**。
> 早先只比对「念的文本」，于是改音色/语速**不会**触发重生成——
> 与当初「改了载体字音频却不更新」是同一类坑，那次是靠人肉发现的。

第一轮复听后 18 → 4 条。

### 最后几个：尾随逗号

剩下 `wū`（屋，两处 key）· `ēn`（恩）· `é`（鹅）怎么调参数都读不稳。
共同点是**这几个字几乎不单独使用**，TTS 训练数据里缺少它们作为独立句子的样本。

对策是给它们补一个**尾随逗号**（`scripts/generate-voices.mjs` 的 `TAIL_FIX_KEYS`）：
那个字不再位于句末，韵律模型就不给它加收尾的降调。多出来的停顿是静音，听不出来。

```
⚠️ 刻意只对清单里的几个用，不全局开。
   换音色 + 放慢之后 102 个拼音已有 98 个读准，
   全局加逗号等于把那 98 个重新赌一次（神经 TTS 未必每次输出一致）。
   复听发现新的读不准，往 TAIL_FIX_KEYS 里加即可，签名会自动触发重生成。
```

**两个已知的死角，只能录真人音频**（`npm run pinyin:record`）：

| 音节 | 为什么换不了字 |
|---|---|
| `dē` `nè` `lè` `ēi` `yūn` `ēng` `ōng` | 汉语里没有干净的单音字载体，已排除出题库 |
| `ēn`（恩） | ⭐ `ēn` 一声的常用字**只有「恩」**（「摁」是四声，其余生僻），无可替换 |

> `é`（鹅）即使读不准也**不影响教学**：它只用于单韵母 e，
> 而那一组按设计不教声调（见 `pinyinSyllables.ts` 的 `SINGLE_FINALS`），
> 选项上显示的是 `e` 不是 `é`。

> **为什么用 msedge-tts 包而不是自己实现协议**：
> 本来照 `generate-icons.mjs` 的路子手写了一版（Node 24 自带全局 WebSocket）。
> 实测**一律 403**：微软给这个端点加了 `Sec-MS-GEC` 时间戳签名，
> 而且比公开资料描述的更严——补上签名仍被拒（已排除时钟偏差）。
> 这是个**私有且在持续加固**的协议，手写实现等于埋雷。

### 3.3 拼音音节（阶段 ⑧ 已完成）

79 个音节，其中 **72 个有汉字载体、已入库**，7 个等真人录音。
见 `data/seed/pinyinSyllables.ts`。

#### ⭐ 关键决定：每个音节挂一个**汉字载体**

Edge TTS 是**文本**转语音，不是拼音转语音。喂它 `bā` 只能靠它猜怎么读；
喂**汉字**「八」则必然读对——常用字的读音是 TTS 的看家本领。

实测确认（`scripts/` 下的探针）：
- 裸拼音文本：四声能产出不同音频，但**不保证读对**
- 汉字：四声不同且必然正确
- SSML `<phoneme>` 音标覆盖：**不可用**（msedge-tts 会转义标签）

#### 选字的三条硬规矩

1. **绝不用多音字** —— 「乐」有 lè/yuè，「晕」有 yūn/yùn，TTS 挑哪个全凭运气。
   这是本表最大的风险来源，写表时已因此撤掉数个"看起来很合适"的字。
2. **优先常用字** —— 生僻字 TTS 也可能读错，且无法靠常识复核。
3. **`char` 与 `pinyin` 必须真的对应** —— 这一列就是给人复核用的：
   懂拼音的人扫一眼「bā → 八」就知道对不对，**不必听音频**。

#### 机器能验什么、不能验什么

| | 谁来验 |
|---|---|
| 声调标记与 `tone` 字段是否一致 | ✅ `pinyinSyllables.test.ts`（实际抓到过 `māng` 配 `tone: 2`）|
| 音节 key 有无重复、汉字是否单字 | ✅ 同上 |
| 同一个字有没有被标成两个读音 | ✅ 同上 |
| **「八」是不是真的读 bā** | ❌ **只能靠人耳** |

#### ⭐⭐ 实测教训：裸拼音会读错声调，已结构性修复

孩子试听后反馈：`á` 读成 `ā`、`ā` 读成 `à`、`ǎ` 读成 `á`、`ē` 读成 `è`、`ō` 读成 `ò`……
**全部出现在没有汉字载体的那批**——也就是只能把拼音串喂给 TTS 的那些。

这比没有声音严重得多：选项上标着 `ā`、播出来是 `à`，是在**明确地教错**，
而学错的发音以后很难改。三条修复：

| 问题 | 修法 |
|---|---|
| P1.3 四声调用裸元音 `ā á ǎ à` | ⭐ 改用「**妈麻马骂**」——教声调的标准范例，四个常用单音字，读音必然正确 |
| P1.1/P1.2 单韵母标了调 | ⭐ 改为**不带调**显示 `a o e i u ü`——课本introduce 单韵母时本就不标调，不作声调声明就无所谓读错 |
| d/n/l 呼读音 `dē nè lè` 无载体 | 改用真实音节「**弟 你 里**」，同样考 d/t/n/l，读音有保证，且更接近真实语言 |

另外补上了能找到的载体字：`凹`(āo)、`肮`(āng)、`椰`(yē)。

**剩下 7 个确实没有干净载体**，已**排除在题库之外**（宁可少几个韵母，也不教错）：

```
dē nè lè  ēi yūn ēng ōng
```

它们在汉语里要么不能独立成音节（eng / ong），要么只有多音字（诶、晕）。
`npm run pinyin:record` 生成录音页，浏览器直接录、自动按正确文件名下载，
7 条两分钟录完。

> ⚠️ **改载体字必须重生成音频。** 脚本原本只补「文件不存在」的 key，
> 于是把载体从「ā」换成「啊」之后文件还在、直接跳过——表里改了，播出来还是旧的错音频。
> 现已改为按「念的文本变没变」判断（台账 `public/audio/voice/.spoken-text.json`），
> 改字必然触发重生成。

#### 试过但不可行的两条路

- **SSML `<phoneme>` 音标覆盖**：Edge 免费端点直接拒绝请求（`<phoneme>` 是 Azure 付费层功能）
- **自动测声调**：写过一个用基频曲线判定声调的分析器，结果 `鸡` 测出 12 个半音的下降、
  `大` 测出接近平调——**假阳性约五成**，因为单字音频有 1.5 秒静音尾巴，
  音高跟踪在衰减段产生倍频错误。做可靠需要正经的 DSP 工作，已放弃。
  **声调正确性目前只能靠人耳**，这就是 `pinyin:check` 存在的理由。

#### `npm run pinyin:check`

生成一张试听页（`public/pinyin-check.html`），把「听完全部音节」变成几分钟的事：
键盘 ← → 切换、空格重听、`1`/`2` 标记，最后一键导出问题清单。

> 校验时重点听：**声调是否分明**（尤其「妈麻马骂」这组）、
> **前后鼻音** `an/ang`、`in/ing` 是否读得出区别、**平翘舌** `z/zh` `c/ch` `s/sh`。
> 发现问题标记出来导出清单——换个载体字重跑 `npm run voices` 即可，
> 台账会自动识别载体变更并重生成。

### 3.4 英语（阶段 ⑨ 已完成）

**158 条**词/短语/整句/字母，全部用英语儿童音色生成，见 `data/seed/englishWords.ts`。

#### 与拼音的关键差别：不需要发音载体

拼音那边每个音节要挂一个汉字，因为把 `bā` 喂给中文 TTS 只能靠它猜。
英语反过来——**喂英文单词给英语音色是母语场景，必然读对**，
`apple` 不存在读成别的可能。所以英语的内容成本远低于拼音：
不用挑载体字、不用怕多音字、不用逐条试听。

#### ⭐ 字母念整句「A is for apple.」

孤立的单个字母**有歧义**：`A` 既是字母名 /eɪ/ 也是冠词 /ə/，TTS 挑哪个不由我们决定。
这是英语侧唯一有发音风险的地方，解法是**把字母放进整句**——
`A is for apple` 里那个 A 只可能是字母名，歧义直接消失，
不必像拼音那样逐条人工试听。

而且这句话本身就是字母教学的标准句式：字母与首字母单词一次带出。

> ⚠️ 字母是脚本里唯一需要**重建**的一段：`LETTER_CARDS` 由规则拼出，
> 正则扫不到成品。脚本 `loadLetters()` 从 `WORDS` 表解析并按同样的句式拼接，
> 结构对不上时**直接失败退出**（不是警告）——
> 静默不同步的后果是「代码改了、播出来还是旧的」，拼音那边已经踩过一次。

#### 一处已知的冗余

`orange` 生成了两条音频（`en.orangeColor` / `en.orangeFruit`），
因为颜色和水果的图形面不同（🟧 / 🍊），而一个词条只能有一个图形面。
多出来的一条约 10KB，不值得为它引入「多词条共用一个片段」的间接层。

### 3.5 混入真人录音

目录结构天然支持混搭：把同名 mp3 放进 `public/audio/voice/` 覆盖即可，
代码与清单都不用改。情感价值最高的几句（宠物台词、鼓励语）最值得这么做。
