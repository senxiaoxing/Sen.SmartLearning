# 10 · 微信小程序可行性评估

> **这份文档管什么**：这个 App 能不能做成微信小程序公开版、卡在哪里、主体和类目怎么选、
> 宠物和积分怎么保住、营业执照怎么办、先做哪个形态。
>
> **不管什么**：小程序版的技术实现方案（另开目录、另开文档）；
> 本项目 PWA 自用版的任何约束调整（**本文结论不改动本项目的硬约束**）。
>
> 调研与讨论 2026-09-14。政策信息来自微信开放文档与开放社区官方页面，
> 工商与税务部分来自各省市场监管局公开办事指南。
> ⚠️ 平台规则变动频繁，**动手前按 §9 清单复核一遍**。

## 0. ⭐ 一句话结论

**能做，但不是把这个 App 搬过去，而是重做一个产品。**

搬过去要付：1.5 万行 UI 重写 + 一场必输的体积战争（20MB 上限 vs 33MB 语音）
+ iPad 上从「主屏图标一点即开」退化成「开微信 → 下拉 → 找」。

而真正值钱的东西——认知误区诊断、逐条校对过的读音、内容表——是能整个搬走的。
所以正确的问法不是「这个 App 怎么变成小程序」，而是
**「这批资产里，哪一块最适合做成一个给别人用的小程序」**。

## 1. 先分清两件事：自用版和公开版

这两件事的约束完全不同，混在一起想必然打结。

| | PWA 自用版（本项目） | 小程序公开版（新项目） |
|---|---|---|
| 用户 | 一个孩子 | 不特定的孩子 |
| 设备 | iPad | 手机为主 |
| 分发 | GitHub Pages + 添加到主屏幕 | 微信搜索 / 转发 |
| 存储 | 纯本地 IndexedDB | 本地 storage + 云存储（只放语音） |
| 审核 | 无 | 备案 + 代码审核 |
| 主体 | 无 | 个体工商户 |
| 结论 | **保持现状，不动** | 另开目录重做 |

**本项目的硬约束一条都不改。**小程序是并行的第二形态，不是这个项目的下一个版本。

> 顺带记一条以后会用上的事实：**纯自用根本不需要过审**。
> 官方口径「备案只影响线上版本，开发版和体验版的更新不受影响」，
> 体验成员 + 项目成员合计上限 180 人。
> 只给自家孩子用发体验版即可——不备案、不提审、不选类目。
> 我们要做的是公开版，所以这条用不上，但别忘了它存在。

## 2. 三本硬账

### 2.1 ⭐ 包体积：20MB 上限 vs 33MB 语音

这是最硬的一条，没有商量余地。

```
小程序主包         ≤ 2MB
单个分包           ≤ 2MB
所有包合计         ≤ 20MB
```

当前资源实测（2026-09-14）：

| 目录 | 数量 | 体积 |
|---|---|---|
| `public/audio/voice` | 1613 条 mp3 | 32.92 MB（平均 20.9 KB/条） |
| `public/audio/bundles` | 14 个 `.bin` | 32.92 MB（同一批的打包版） |
| `public/audio/sfx` | 6 个 | 0.10 MB |
| `public/icons` | — | 0.01 MB |

代码和 seed 内容还要再吃掉几 MB（`data/` 生产代码 12362 行，大部分是识字/古诗/词卡内容表）。

**唯一现实的出路**：语音改为首次进入时从**微信云开发的云存储**下载到本地。

```
云存储（免费额度 5GB 存储 + 5GB 下行/月）   只放语音包
文件系统（上限 200MB）                      下载后的本地缓存
```

好消息是迁移成本低：现在就是 14 个 `.bin` 分包 + 索引的形状，
`platform/voiceBundles.ts` 只有 62 行，本质上只是换个下载源。
云开发的域名不需要 ICP 备案、不需要配置合法域名。

按现有分包量，如果只做语文启蒙那一块：

```
pinyin0  1.21 + hanzi 6.12 + poem 11.82 ≈ 19.15 MB
english  8.47 MB
core     3.60 MB   pet 1.72 MB
```

单块都在云存储免费额度内游刃有余（33MB 全量 ÷ 5GB 月流量 ≈ 150 次全量下载/月）。

### 2.2 iPad 上是体验倒退

iPad 微信从 6.7.2 起支持小程序（主界面下拉进入）。但：

```
❌ 没有主屏幕图标 —— 现在 PWA 一点即开，小程序要「开微信 → 下拉 → 找」
⚠️ iPad 上的渲染适配（rpx 换算、横屏）要实机验证，不能照搬手机布局
```

CLAUDE.md 自己写着「通往主要功能的路上每多一道门，就流失一部分」。
这里多了两道，而使用者是六岁的孩子。

**结论：小程序版按手机设计，别把 iPad 当目标设备。**iPad 上继续用 PWA。

### 2.3 重写量约 1.5 万行

`domain/` 禁 import 浏览器 API 那条铁律在这里兑现了回报：

| | 行数 | 去向 |
|---|---|---|
| `domain/` 生产 | 14094 | ✅ 原样复用 |
| `domain/` 测试 | 9217 | ✅ 原样复用 |
| `data/` 生产 | 12362 | ✅ 内容表复用，仓储层换掉 |
| `data/` 测试 | 4615 | ✅ 复用 |
| `stores/` | 1091 | ✅ zustand 是纯 JS，基本复用 |
| **小计可复用** | **≈ 27500 行** | |
| `features/` | 7164 | ❌ 重写 |
| `components/` | 4712 | ❌ 重写 |
| `items/` | 1940 | ❌ 重写 |
| `platform/` | 1449 | ❌ 重写 |
| **小计重写** | **≈ 15300 行** | |

死掉的依赖与替代：

| 现在 | 小程序 |
|---|---|
| React 18 + Vite | Taro 4（React 18 + TS 原生支持） |
| `react-router` | Taro 路由 |
| `framer-motion` | ❌ 全废，改 CSS 动画 |
| `dexie` / IndexedDB | `storage`（10MB）+ 文件系统（200MB） |
| `howler` | `InnerAudioContext` |
| Web Speech API | ❌ 没有 |
| PWA / Service Worker | ❌ 没有 |

✅ **一个好消息**：小程序 `WebAudioContext` 支持 `decodeAudioData` 和 `createBufferSource`，
所以 `platform/speechClips.ts` 那套**裁静音 + 片段拼接**能移植，不用推倒重来。

## 3. 主体：个体工商户

个人主体有两条硬伤：**不能用微信支付**、**教育类目受限**。
要做公开版、要推广、要有变现可能，就别用个人主体。

| | 个人 | 个体工商户 | 有限公司 |
|---|---|---|---|
| 认证费 | 30 元/年 | 300 元/年 | 300 元/年 |
| 微信支付 | ❌ | ✅ | ✅ |
| 教育类目 | 受限 | 企业类目 | 企业类目 |
| 流量主 | ✅ | ✅ | ✅ |
| 小程序数量 | 5 | ⚠️ 说法不一（见 §9） | 50 |
| 注销 | — | 简单 | 麻烦 |

**结论：个体工商户。**别指望以后从个人主体升级上来，一步到位。
只有在「要做很多个产品 / 要拿投资 / 要开专票」时才升级到有限公司。

流量主门槛是**累计 UV 1000**（不是日活），无违规记录。
个体工商户的流量主收益**支持委托经营者个人账户收款**，不强制开对公账户。

## 4. 类目：躲开「培训」两个字

这是比宠物危险得多的地方。

微信企业类目下的教育培训各子类目普遍要求《民办学校办学许可证》，
而**义务教育阶段学科类校外培训机构已不再审批新的**——这张证根本办不下来。
往「培训」上靠 = 死路。

**策略：定位成"学习工具"，不是"课程培训"。**产品形态要配合：

```
✅ 不卖课、不排课、无教师、无直播、不收费  → 不构成培训
✅ 走「教育信息服务 / 教育信息展示」或「工具」类目 → 不需要办学许可证
```

### ⭐ 类目绝不能多选

审核规则原文：*「小程序服务类目所对应的页面中的核心内容必须与该类目一致，
必须保证用户在该页面能使用该服务类目，不得隐藏，不得进行多次跳转」*。

**每多选一个类目，就多一个必须有实际内容支撑的页面，多一条被拒理由。**
类目在后台随时可改，不需要提前占位。

## 5. 宠物 + 积分：不用砍

风险被高估了。微信明令禁止的游戏化是这几条，我们一条都不沾：

| 禁止项 | 我们的情况 |
|---|---|
| 赌博、有奖竞猜、抽奖 | ❌ 不沾 |
| 随机抽取虚拟道具 | ❌ 红线第 6 条「不做随机奖励（抽卡/开箱）」 |
| 用户间道具定向转移 | ❌ 单机无社交 |
| 虚拟支付 / 诱导充值 | ❌ 积分不可用钱购买 |
| 诱导充值排行榜 | ❌ 红线第 3 条「三只宠物绝不比较、不排名」 |

⭐ **产品红线本身就是「这不是游戏」的证明材料。**
判定游戏的核心是「是否提供可独立游玩的玩法」，而宠物脱离学习在这里根本不存在。

### 要做的规避动作（全是零成本的）

```
1. 首页第一屏必须是学习入口，不是宠物
   —— 审核员打开的第一眼决定他给你归哪个类目
2. 不做「不学习也能玩」的闭环
   —— 喂食/装扮不能自己产出乐趣，必须由学习驱动
3. 改字眼：「商城 / 兑换商城」→「小屋 / 奖励」
   全局去掉「闯关」「挑战」「PK」「对战」
4. 现实兑换券页加一句：由家长自行设定，本小程序不提供任何实物或服务
5. 提审备注主动交代：宠物为学习进度可视化，
   无独立玩法、无随机奖励、无排行、无交易
```

这五条做完，宠物 + 积分过审风险很低，**不需要砍任何功能**。

## 6. ⭐ 真正的雷：儿童个人信息

免费云数据库很诱人，但**云存储用，云数据库先别用**。

一旦用云数据库存孩子的学习记录，就构成**收集不满 14 周岁儿童个人信息**，触发
《个人信息保护法》第 31 条：必须取得监护人**单独同意**，
还要单独制定儿童个人信息处理规则。这比宠物麻烦十倍，且是实打实的法律责任。

### 推荐架构

```
云存储（免费 5GB/5GB月）   只放语音包 → 纯 CDN，不含任何用户数据
storage（10MB）           学习记录、掌握度、积分 → 纯本地，文本绰绰有余
文件系统（200MB）          下载下来的语音包 → 本地缓存
云数据库                   ⛔ 暂不用
```

**不收集任何个人信息 → 隐私保护指引写「不收集」→ 审核路径最短，法律风险为零。**
本项目「纯本地不上云」的设计在这里反而成了合规优势。

代价：换设备 / 清缓存数据会丢。
以后真要做云备份，做成**用户主动开启的可选功能**，到那时再补监护人同意流程。

## 7. 产品形态：先做哪一个

### 先记一条现在这个 App 里没有、公开版必须有的东西

**一个值得发到家长群的产出物。**

小程序没有应用商店式的自然流量，全靠搜索 + 转发，
而儿童教育最好的传播场景就是家长群。自用版不需要这个，公开版没有它就没有增长。

### 三个候选方向

| 方向 | 差异化 | 审核风险 | 日活 | 保留宠物 |
|---|---|---|---|---|
| **A. 口算错因诊断** | ⭐ 别人给对错，我们给「她是凑十丢了进位，还是做成了减法」 | 低（工具类目） | 中高 | ✅ 有判分 |
| **B. 读音保准的语文启蒙**<br>（拼音 + 识字 + 古诗） | ⭐ 多音字逐条人工听过 | 最低（纯浏览，正是「信息展示」的形状） | 中 | ❌ 无判分 |
| **C. 家庭奖励约定**<br>（宠物 + 积分 + 兑换券独立） | 「家长上架 = 承诺」的双向机制少见 | 最低（生活服务类目，完全避开教育） | 高 | ✅ 就是它本身 |

### ⭐ 推荐 A 打头阵

- **它是唯一抄不走的东西**。市面上的口算小程序几乎全是随机干扰项，
  `misconceptionTag` 是真稀缺——这正是 CLAUDE.md 红线「干扰项必须有诊断性」的价值兑现
- 数学模块语音占比小，**体积战争最好打**
- 有判分 → 宠物 + 积分完整保留
- 天然有产出物：一份「孩子卡在哪一步」的家长报告，那是能截图发群里的东西，
  而这恰恰是别的口算小程序给不出的

B 的差异化也很硬（家长真怕 App 读错音教坏孩子，而把「鬓毛衰」念成 cuī 的小程序遍地都是，
见 design/07 §多音字改写），但它天生没有判分，宠物挂不上去，
**适合作为第二个 Tab 而不是第一个产品**。

C 日活最高、审核最简单，但脱离学习内容就丢了护城河，**不建议单独做**。

## 8. 营业执照：办理与成本

### ⭐ 先分清两个概念

| | 经营范围（工商局） | 服务类目（微信后台） |
|---|---|---|
| 归属 | 营业执照上，一个主体一份 | 每个小程序单独选 |
| 改动成本 | 要走变更流程，麻烦 | 后台随时改 |
| 策略 | **尽量写宽** | **只选实际有的**（见 §4） |

**策略正好相反，别搞混。**

### 经营范围怎么写

一般项目（登记即可经营）**写多了不增加任何成本**，一次写足：

```
一般项目：技术服务、技术开发、技术咨询、技术交流、技术转让、技术推广；
软件开发；信息技术咨询服务；计算机系统服务；数字内容制作服务（不含出版发行）；
教育咨询服务（不含许可类教育培训活动）；动漫游戏开发；
广告设计、代理；广告制作；广告发布；玩具、动漫及游艺用品销售；文具用品零售
```

```
⭐「教育咨询服务（不含许可类教育培训活动）」那个后缀是关键
   —— 它是一般项目，不需要办学许可证，正好对应 §4 的「不往培训靠」
⛔ 许可项目别乱写（出版物经营、网络文化经营、增值电信业务）
   —— 写了办不下来会卡住登记
⚠️ 以后若想做小游戏类目，需要版号等资质，个体工商户基本拿不到
   —— 真有这个打算，主体要重新考虑有限公司
```

### 网上办理流程

营业执照办理**全程免费**，电子营业执照与纸质同等效力。各省系统不同，大致流程：

1. 搜「**所在省份 + 市场监督管理局 + 个体工商户 全程电子化登记**」找本省入口，
   或从国家政务服务平台进
2. 实名认证（人脸识别）
3. 填：名称（多数地方已自主申报，不用预先核准）、经营场所、经营范围
4. **经营场所**：一般可用自家住址，多数省份支持「住所申报承诺制」，
   需房产证或租赁合同
5. 数字证书签名提交 → 审核约 1–3 个工作日
6. 领电子营业执照（微信搜「电子营业执照」小程序可下载）
7. **领照后 30 天内做税务报到**（很多地方已自动同步）

### 后期维护费用

| 项目 | 费用 | 频率 | 能省吗 |
|---|---|---|---|
| 营业执照办理 | 0 | 一次 | — |
| 刻章 | 0～300（多地免费赠送） | 一次 | — |
| 工商年报 | **0** | 每年 1/1–6/30 必做 | ⛔ 漏报进经营异常名录 |
| 税务申报 | **0**（电子税务局自行零申报） | 每月/每季 | ✅ 自己做 |
| 代理记账 | 500～1000/年 | 每年 | ✅ 无业务时不需要 |
| **微信小程序认证** | **300/年** ⭐ | 每年 | ❌ 不能省 |
| ICP 备案 | 0 | 一次 | — |
| 对公账户 | 0～1200/年 | 每年 | ✅ 可不开 |

```
⭐ 真正的固定成本只有微信认证 300 元/年
⚠️ 它已从一次性改为年审制。过期后线上版本还能跑，
   但无法再提交新版本审核 —— 等于产品被冻结，别忘了续
⛔ 零申报必须按时做，即使完全没收入
```

### 备案

2023-09-01 起小程序须完成 ICP 备案才可上架。
平台初审 1–2 个工作日，各省通信管理局 1–20 个工作日。免费。

```
4. 新开目录，写那边的 CLAUDE.md
   —— 约束重写：体积红线、云存储边界、审核禁区、儿童信息红线
5. 从方向 A（口算错因诊断）开始
```
