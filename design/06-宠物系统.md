# 宠物系统

> 按「**科目 × 年级**」划分的伙伴，各自独立成长。
> 12 级 / **6 个形态**，性格与台词各不相同。
>
> 一年级：语文小飞龙「墨墨」· 数学小企鹅「团团」· 英语小熊猫「波波」

---

## 0. 为什么按年级换宠物

每升一个年级换一批新伙伴，让每个学年都有：
- **明确的终点** —— 把这一年的三只养到最终形态
- **新的期待** —— 升年级时认识新伙伴

成长曲线据此校准：**学完一个年级的内容，宠物正好满级**（见 §2）。
上一年级的宠物保留不再成长，记录着那一学年的成果。

新增年级时只需在 `data/seed/pets.ts` 追加三只定义，
成长逻辑、UI、仓储都不用改。

---

## 1. 为什么是三只而不是一只

单宠物系统有个固有缺陷：养到高级后升一级要很久，陷入**动力真空**。

三条并行成长线保证**总有一只接近升级**。而且科目区分度更高——
孩子打开 App 看到企鹅就知道「今天是数学」，认知负担更低。

### ⚠️ 必须规避的风险：强化偏科

三只独立成长，孩子必然偏向喜欢的科目。企鹅养到 10 级、龙还是蛋，
这**强化**了不平衡，还会让她对落后的那只产生愧疚。

三条硬性约束（已写入 CLAUDE.md 产品红线）：

```
❌ 绝不显示宠物之间的比较：不排名、不并列进度、不写「最高级的是…」
✅ 落后的宠物台词是「好久不见，我有点想你」，绝不是「你都不理我」
✅ 未开放科目的宠物显示「还在睡觉，等课程准备好就醒来」，
   而不是一直停在蛋阶段——那看起来像孩子没养好，实际是 App 还没做完
```

最后一条尤其重要：题库没建好的科目，那只宠物就永远不会长大——
让孩子背这个锅是不公平的。

> ✅ 阶段 ⑧⑨ 之后三科题库齐备，三只宠物**全部醒着**。
> 这条规则依然有效：以后加新科目、升新年级时，还会用到它。
> 「科目已开放」的判据是**真的出得了题**，由 `pets.test.ts` 强制校验——
> 醒着却一道题都出不来，比还在睡觉更糟。

## 2. 成长曲线：开头极快，满级 ≈ 学完一年

曲线要同时满足两个目标，缺一不可。

| 等级 | 累计经验 | 形态 |
|---|---|---|
| Lv1 | 0 | 🥚 蛋 |
| **Lv2** | **15** | ⭐ **第一轮做完就到** |
| **Lv3** | **45** | 🐣 **破壳（第二轮就变身）** |
| Lv4 | 100 | |
| **Lv5** | **190** | 🐧 小企鹅 |
| Lv6 | 320 | |
| **Lv7** | **500** | 🧣 数数小能手 |
| Lv8 | 750 | |
| **Lv9** | **1080** | 🎒 计算高手 |
| Lv10 | 1500 | |
| **Lv11** | **2100** | 👑 企鹅王（带光效） |
| Lv12 | 3000 | 满级 |

**经验来源**

| 行为 | 经验 |
|---|---|
| 答对一题 | +2 |
| ⭐ 订正答对 | +1 |
| 完成一轮 | +5 |
| 掌握一个知识点 | +15 |

### 目标一：开头极快

一轮 10 题全对 ≈ 25 经验，因此**第一轮必定升级、第二轮就能看到第一次变身**。

> 孩子第一次使用时若看不到宠物变化，养成系统对她就只是个不动的图标。
> 这是整套机制能否建立起来的关键。

### 目标二：满级 ≈ 学完一个年级

一年级数学 48 个知识点、按 `estimatedItems` 累计 1570 题 ≈ 157 轮。
满级定在 3000 经验（约 120 轮全对）与之匹配——**学完一年正好养到最终形态**。

后期间隔拉长没关系：三只宠物轮换着接近升级，动力不会断。
这条匹配关系由 `growth.test.ts` 用知识点数据实际校验，改动曲线时会立刻发现失衡。

### 6 个形态，每 2 级一变

12 级 ÷ 6 = 每 2 级变身一次，让孩子做完两三轮就能看到宠物真的不一样了。

关键是**六个形态视觉上要真的能区分**——同一个 emoji 只靠大小变化远远不够，
因此每个形态配不同装饰，而且**装扮是累加的**：

```
🥚 → 破壳 → 素体 → ＋围巾 → ＋披风 → ＋皇冠✨
```

累加而非替换是刻意的：孩子攒下来的东西一直挂在身上，
成长感比每进阶一次就换掉上一件强得多。

光效只给最终形态，才有分量。这些约束由 `pets.test.ts` 强制校验
（形态数、尺寸递增、装饰组合不重复、光效唯一、槽位不冲突、装扮只增不减）。

## 3. 性格设计

台词是宠物系统里最便宜也最有效的部分。一个会说「让我数数看～」的企鹅，
和一个只显示等级数字的图标，对孩子完全是两种东西。

| 宠物 | 科目 | 性格 | 口头禅 | ⭐ 专属音色 |
|---|---|---|---|---|
| 🐧 团团 | 数学 | 认真、爱数数、有点小得意 | 让我数数看～ | `YunxiaNeural` 男童声，像同班的小男孩 |
| 🐉 墨墨 | 语文 | 话痨、爱讲故事、文绉绉 | 本龙又学会一个字！ | `YunxiNeural` 阳光青年，「妙哉」的小学者 |
| 🐼 波波 | 英语 | 好奇、爱模仿、中英夹杂 | This is 好吃的！ | `XiaoxiaoNeural` 温暖女声，软语慢速 |

每只五个场景各有台词池（问候 / 答对 / 答错 / 升级 / 久别重逢），
随机取用避免重复。

**每只有自己的声音**（2026-08 起）：与旁白的少女声合计四个声部——
男童 / 青年男 / 温暖女 / 少女，孩子不用看屏幕就知道是谁在说话。
台词（`petline.*`）按物种路由音色；宠物叫昵称时，名字用**它自己音色**的
昵称变体片段（`name.penguinXiaoenbao` 等），绝不出现「一句话两个人说」。
音色与韵律定义在 `scripts/generate-voices.mjs` 的 `PET_VOICES` / `PET_PROSODY`，
变体挑选逻辑在 `domain/encourage/petSpeaker.ts`。

**答错台词必须温和**（产品红线）：
- 团团：「嗯…我们再看看」「没关系，我也常常数错」
- 墨墨：「无妨无妨，再想想」「本龙当年也念错过～」
- 波波：「Oh no～再试试」「没关系 no problem」

## 4. 三条设计禁令

**① 不做随机奖励**
成长必须是确定的、努力可预期的。抽卡、开箱、随机掉落那套是赌博心理，
不该出现在儿童学习产品里。做对多少题 = 涨多少经验，就这么简单。

**② 经验只增不减**
`PetState.exp` 是唯一的成长数据，等级和形态都由它推导，不单独存储。
存冗余的 level 字段迟早会和 exp 不一致，而不一致的表现是
「宠物等级莫名其妙变了」——对孩子来说非常伤。

**③ 升级不打断学习流**
升级提示放在**小结页**统一展示，不在答题中途弹窗。
形态变化给更隆重的展示，普通升级保持轻量——每轮都大张旗鼓反而失去分量。

## 5. ⭐ 让孩子给宠物起名

最强的情感绑定手段，成本几乎为零。宠物页有显眼的「✏️ 给它起个名字」入口。

**从预录名单里点选，不用键盘**（`features/pet/PetNamePicker.tsx`）：

- 候选 = 这只伙伴的默认名 + 共享候选池（`data/seed/petNamePresets.ts`，
  每个名字都有预生成语音片段 `petname.*`）
- **点一下候选名 = 念出来 + 选中**——孩子不识字，听着挑，起名完全是她自己的事
- 名字有片段意味着升级那句「毛毛升到 3 级啦」**永远不会降级成机器音**
  （这曾是 design/07 §2.5b 表里「孩子改过名 → 整句 TTS」的口子，已封死）
- 候选名**绝不用多音字**（「乐乐」有 lè/yuè 两读），理由与拼音载体字同一条铁律

改成点选后，这里不再是「全 App 唯一需要键盘的地方」——App 从此全程无键盘。
旧档案里键盘起的名字仍然显示，只是那只宠物的升级播报走 TTS，重新起名即恢复。

## 6. 美术方案：先用 emoji 跑通机制

12 个形态 × 3 只 = 36 张美术图会卡住整个系统的开发，
而**机制验证比美术重要**——孩子先玩起来，形象随时可以换。

当前用 **emoji + 尺寸 / 光效 / 槽位配饰**表现六个形态：

| 等级 | 企鹅（数学） | 飞龙（语文） | 熊猫（英语） |
|---|---|---|---|
| Lv1-2 | 蛋 | 蛋 | 蛋 |
| Lv3-4 | 破壳 | 破壳 | 破壳 |
| Lv5-6 | 小企鹅 | 小飞龙 | 小熊猫 |
| Lv7-8 | ＋围巾 数数小能手 | ＋眼镜 识字小龙 | ＋竹叶 单词学徒 |
| Lv9-10 | ＋披风 计算高手 | ＋小翅膀 读书龙 | ＋书包 双语熊猫 |
| Lv11-12 | ＋皇冠✨ 企鹅王 | ＋大翅膀＋角✨ 文曲龙 | ＋学士帽✨ 熊猫博士 |

替换为真实美术时**只需改 `components/PetAvatar.tsx`**，其余逻辑不受影响。
接口已按这个前提设计（`PetStageAppearance` 描述外观，与成长逻辑解耦）。

### 槽位结构

配饰不是一个字符串，而是带挂载点的列表：

```ts
type AccessorySlot = 'head' | 'face' | 'neck' | 'back'

interface StageAccessory {
  slot: AccessorySlot
  kind: string   // 语义名，渲染层据此决定画什么
  emoji: string  // 占位，SVG 部件就位后可删
}
```

有了槽位，围巾才能长在脖子上、皇冠才能戴在头顶——
旧实现把所有配饰一律钉在头像右上角，看着像贴纸而不是穿戴在身上。

两条由测试守住的规则：

- **一个槽位只能挂一件**，否则两顶帽子会直接叠在一起
- **已经占上的槽位不会在下一级空掉**（同槽位允许升级，如小翅膀换大翅膀；
  破壳的蛋壳是唯一例外——那是要脱掉的，不是攒到的）

### 形象方向

三只的形体已定稿为**手写内联 SVG**（非 Lottie / 非位图）——
零新依赖、能做眨眼与锚点配饰、48px 头像下依然锐利，且形象本身可由 AI 直接迭代。

| | 参考 | 形象色 | themeColor |
|---|---|---|---|
| 团团 | 《马达加斯加的企鹅》 | 深蓝 `#21395F` | `#63B3F2` |
| 墨墨 | 小火龙 / 喷火龙 | 绿 `#5BB94E` | `#A78BFA` |
| 波波 | 未定 | — | `#5FD3A6` |

⚠️ **形象色与 themeColor 刻意分离**。墨墨形象走绿，但主题色保持紫——
绿色 `#5FD3A6` 是波波的，进度条要是也变绿两只就撞了。

墨墨的核心符号是**尾焰**，三层各自跳动（周期互不整除，叠加永不重复），
且随等级从 0.6 倍长到 1.35 倍——蛋阶段先从壳顶裂缝冒一缕烟作预告，
构成一条从烟到火的完整线索。

### 新增年级的做法

在 `data/seed/pets.ts` 追加三只定义即可，形如：

```ts
const PENGUIN_G2: PetDefinition = {
  id: 'penguin-g2', subject: 'math', gradeLevel: 'G2',
  defaultName: '…', species: '…', themeColor: '…',
  stages: [ /* 6 个形态 */ ],
  personality: { /* 口头禅 + 五类台词 */ },
}
```

然后加进 `PET_DEFINITIONS`。仓储、成长、UI 全部自动适配。

## 9. 宠物小屋与商店

### ⭐ 一间共享小屋，不是三个房间

分房的话孩子必然先装扮她最喜欢的那只，另外两只的房间一直空着——
她每次打开都看到「波波家里什么都没有」。**那是红线第 3 条「三只之间绝不比较」
的另一种形式，而且更具体**：等级差距是学习自然产生的，房间空着却是她自己选的。

同一件家具要买三次还会让她开始算账「我要不要也给波波买一个」——
一旦她做这个取舍，她就是在给三只排序。

所以：三只住一起，家具只买一次，这是「**你们的家**」。

### 家具位置写死，一位一件

买了自动摆好，**家具没有任何布置操作**——一年级孩子不该做「摆放」这种事。
也不做「红地毯 / 蓝地毯」二选一：二选一会制造「我买错了」的懊悔，
而她不识字、颜色偏好又不稳定。

> ⭐ 可以自由摆的只有三只伙伴（§10）。让她摆家具是让她做布局决策，
> 而挪伙伴不存在「摆错」——怎么摆都是她的家。

加内容 = **加新位置**（窗台的花、天花板星星灯、门口地垫），
每个新位置就是一个新空位，空位比已获得更能驱动行为。

### ⚠️ 零食不等于喂养

零食（10~25 分）**买入即消耗**：**每只头顶各掉一份** → 各自吃掉 → 一起开心地蹦一下。
实现在 `features/shop/TreatFeast.tsx`。
**不加经验、不涨好感、没有饱食度。**

⚠️ **三只各拿到一份，不是共分一块。** 最初只在正中间掉一块，
孩子实测反馈「只有中间出现一个小饼干，应该是三个宠物都吃到」——她说得对：
一块饼干配三只，画面上就是有两只没吃着，而「谁吃到了」正是红线第 3 条
最不该出现的那种比较。

⚠️ **动画将近 3 秒，不要为了「干脆利落」再砍短。** 原来 1.25 秒，
孩子反馈「太短了」，掉下来还没看清是什么就没了。四拍里那一拍「停住」
（1.0 秒）是关键——这是花掉星星唯一能看见的回报。

⚠️ 零食**不走**「星星变成了它」那段转化动画（那是家具和现实券用的）——
零食不会被留下，「变成」讲不通。买它的全部意义就是那一小段吃的画面。

喂养系统在 design/02 §3.11、design/03 §4.5 与本文早期版本三处都被明确移除过，
理由是它必然带来「没喂 = 宠物变惨」的惩罚感。零食是一次性的开心，仅此而已。

也**不做「喂哪一只」的选择**——那和买三次是同一个陷阱，又在让她排序。
因此三样都是通吃的东西（小饼干 / 水果篮 / 大蛋糕），不是小鱼干、竹叶这类专属食物。

### 商店入口只在小屋里

买完东西直接看到它摆进屋里，那个瞬间是整个功能的高光。

⚠️ 刻意**不放**在首页和小结页——每轮做完都被引导去花钱，会把学习变成打工
（与「升级提示不在答题中途弹窗」是同一个道理）。

## 10. 小屋的整屏布局与自由站位

孩子实测反馈「小屋要大一点，最好能整屏占满」+「小屋太单调了」。
两句话说的是同一件事：**这不像一个能待着的地方**。完整来龙去脉见
[05-孩子反馈与响应.md](./05-孩子反馈与响应.md) 第 7~8 条。

### 铺满整屏：背景铺满 + 舞台等比

家具画在 400×300 的固定坐标里，直接拉伸会变形，按比例裁切又会切掉挂画和书架。
所以分成两层：

```
墙 / 地板 / 踢脚线 / 地板缝   CSS 横带，左右各溢出 100vw、上下各溢出 100vh
家具 + 伙伴                    留在中间那块严格 4:3 的舞台里，等比缩放
```

舞台宽 `min(100%, 100dvh × 4/3)`。两层的地面线共用
`RoomBackdrop.ROOM_FLOOR_TOP`（= 196/300），改一处必须改两处，
对不上会在墙地交界出现一条谁也说不清是什么的横缝。

### 桌子是免费的固定陈设，不是第七件家具

把桌子做成商品，等于把她提出的问题变成一个要攒 400 分才能解决的问题。
商店的职责是往屋里**加东西**，不是让屋子在买之前立不住。

桌子贴着后墙摆在正中，中间那只伙伴站在它前面挡住一截桌腿——
**那一点遮挡就是「有前后」的全部来源**，屋子因此不再是一张平面图。

### 站位：存比例，记左上角

```ts
PetState.roomX / roomY   // 舞台宽/高的 0~1，指向宠物盒子的左上角；可缺失
```

- **存比例不存像素**：换设备打开屏幕尺寸就变了，像素会让三只跑到屏幕外
- **记左上角不记中心**：中心定位要在 framer-motion 的 `x`/`y` 之外再叠一层
  `-50%` 位移，两者会争同一个 `transform`，结果是一拖就跳
- **缺失 = 从没摆过**，回落到默认布局（左 / 中偏前 / 右）。
  不把默认值写进库里，否则以后想调默认布局就动不了已有档案

可及范围 `ROOM_SPOT_BOUNDS` 守两条：

1. 脚不能高过地面线——再往上就站到墙上去了
2. 也不能低到藏进底部那条「去商店逛逛」后面——
   她刚摆好就看不见了，只会以为自己弄丢了一只

⚠️ 这几个数与 `RoomPet.PET_REFERENCE_WIDTH`（伙伴随舞台放大的基准宽度）
绑在一起：伙伴放大了就得收窄边界，否则最终形态会有一截露到舞台外。
由 `roomSpot.test.ts` 的边界用例兜底。

### 点一下会回应，但**进屋不自动打招呼**

点击 = 随机一句该伙伴的 `greet` 台词（预生成音频，自己的音色）+ 气泡 + 跳一下。
台词不带昵称——每一句都喊名字会从「它记得我」变成「它只会喊我名字」。

⚠️ **整层只有 `RoomPets` 一处发声**。三只各自持有气泡、各自 `say()` 的话，
她连点两下就会听到两句叠在一起（`say()` 是打断式的）。

⚠️ **不做进屋自动问候**。宠物页那样一进去就说话，在这里做不到：
得先挑一只来说，而挑哪只都是在三只之间排序（红线第 3 条）。
她点谁谁说，这本身就是最好的答案。
