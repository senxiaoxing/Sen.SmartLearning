# 部署与上机指南

> 目标：把 App 装到 iPad 主屏幕上，让孩子点开图标就能用，离线也能玩。
> 成本 **¥0**，全程不需要 Mac、不需要 Apple 开发者账号、不需要审核。

---

## 0. 为什么必须「添加到主屏幕」

这一步不是可选的美化，而是**数据安全的前提**。

Safari 的 ITP（智能防跟踪）策略会清理 **7 天未访问**站点的 IndexedDB 数据。
孩子一个假期没打开，回来发现学习进度、掌握度、错题记录全没了。

**但已「添加到主屏幕」的 PWA 不受此限制。** 所以：

```
❌ 在 Safari 标签页里收藏着用   →  数据随时可能被清
✅ 添加到主屏幕，从图标启动     →  数据受保护，且可离线
```

App 里已内置提示（`InstallPrompt`），检测到 iOS Safari 且未安装时会提醒家长。

## 1. 部署方式选择

| 方式 | HTTPS | 离线可用 | 需要电脑开着 | 适用场景 |
|---|---|---|---|---|
| **A. GitHub Pages** ⭐ | ✅ 自动 | ✅ | ❌ | **本项目正在用的方式** |
| B. Cloudflare Pages / Vercel | ✅ 自动 | ✅ | ❌ | 备选，换用需改 `BASE` |
| C. 局域网直连 | ❌ | ❌ | ✅ | 开发调试，改一行立刻看效果 |

> ⚠️ **Service Worker 必须 HTTPS 才能注册**（localhost 例外）。
> 走局域网 HTTP 虽然能打开、能添加到主屏幕，但**没有离线能力**，
> 且每次用都要电脑开着跑 dev server。只适合开发期快速迭代。

## 2. 方式 A：GitHub Pages（当前采用）

### 2.1 一条命令

```powershell
npm run deploy
```

它等于 `npm run build && node scripts/deploy-pages.mjs`：

1. `bundle-voices` 重新打包语音包 → `tsc --noEmit` → `vite build` 产出 `dist/`
2. `scripts/deploy-pages.mjs` 把 `dist/` 推到本仓库的 **`gh-pages` 分支**

线上地址：**https://senxiaoxing.github.io/Sen.SmartLearning/**

> ⚠️ `dist/.nojekyll` 必须跟着上去（脚本用 `cpSync` 整目录复制，点文件自然包含）。
> 少了这个文件，GitHub Pages 会用 Jekyll 处理站点，
> 把以下划线开头的目录（如 Vite 产出的 `_headers`）直接忽略掉。

### ⭐ 2.1a 为什么自己写脚本，不用 `gh-pages` 包（2026-09-02）

原来是 `gh-pages -d dist -t`。**文件数涨到一定程度后它必然失败**：

```
Error: spawn ENAMETOOLONG   at Git.rm (gh-pages/lib/git.js:146)
```

它清理旧文件时，把 glob 展开出的**每一个路径**都拼进同一条 `git rm` 命令
（`lib/git.js` 的 `Git.prototype.rm`）。本项目光音频就有 1300 多个文件，
命令行长度直接撞上 Windows 的 32767 字符上限——而开发机只有 Windows
（CLAUDE.md 硬约束第 1 条），换台机器绕过去这条路不存在。

自己写的版本用 **git worktree**，删除旧文件只要 `git rm -r -f -- .` 一个 pathspec，
与文件数无关；语音包再翻十倍也不会碰到这条限制。

顺带修掉了一处**从没被清理过的残留**：`gh-pages` 包的删除步骤用 globby 匹配，
而 globby 默认不匹配点文件，于是 gh-pages 分支上一直躺着一份 main 分支的
`.gitignore`（在那里毫无意义）和一个 `public/` 目录。新脚本的 `git rm -r`
不区分点文件，它们已随 2026-09-02 那次部署一起清除。

脚本在推之前会拦两件事，**这两条是防线不是校验**——它先删光分支上的文件再放新的，
推错了线上就是白屏，而 PWA 还会把那个白屏缓存到孩子的 iPad 上：

- `dist/index.html` 不存在 → 中止
- `dist/` 文件数少于 50（正常有 1300+）→ 中止

### 2.2 ⭐ `BASE` 必须与仓库名一致

GitHub Pages 把项目站点放在 `/<仓库名>/` 子路径下，
因此 `vite.config.ts` 里写死了：

```ts
const BASE = '/Sen.SmartLearning/'
```

改仓库名、换自定义域名、或换回根路径托管（Cloudflare/Vercel）时，
**必须同步改这里**，否则打包产物全部 404、页面纯白。

`start_url` 与 `scope` 也都取自它——这两个字段错了，
「添加到主屏幕」出来的图标会打不开，或者跳出全屏模式。

### 2.3 缓存策略

`public/_headers` 会随构建带到 `dist/`：

```
sw.js / index.html          → no-cache（否则新版本永远推不下去）
assets/*                    → 永久缓存（文件名带内容哈希）
```

> ⚠️ GitHub Pages **不读 `_headers`**（那是 Cloudflare/Netlify 的格式），
> 所以上面这份策略当前**一条都没生效**。文件留着只是为了将来换回 Cloudflare 时不用重写。
>
> ⛔ 别把它当成「更新问题已经解决了」的证据。在 GitHub Pages 上，
> 让新版本落地的是 Service Worker 自己的更新流程（§5.1）——
> 曾经就是误以为这里配好了、SW 那边又漏了关键一步，导致连续多个版本没更新上，
> 详见 §5.2。

### 2.4 隐私说明

GitHub Pages 只托管**代码和图标**。
孩子的学习数据全部存在 iPad 本地的 IndexedDB 里，**不会上传到任何服务器**。

⚠️ 但仓库若是 public，代码与地址都是公开可访问的。
本项目纯自用、不含任何个人数据（昵称、生日等都只存在设备本地，
不进仓库），因此可以接受。

## 3. 方式 C：局域网直连（开发调试用）

> 编号沿用最初的 A/B/C，方式 B（Cloudflare Pages / Vercel）留作备选未展开。
> 换过去只需把 `BASE` 改回 `'/'` 再按各家文档接仓库即可。


```powershell
npm run dev -- --host
```

输出里找 Network 地址：

```
  ➜  Local:   http://localhost:5173/
  ➜  Network: http://192.168.1.108:5173/     ← iPad 用这个
```

iPad 连**同一 WiFi**，Safari 打开该地址。改代码后 iPad 上立刻热更新。

> 这是 PWA 路线相对原生开发的最大红利：改一个按钮颜色，
> 抬头就能在 iPad 上看到孩子会看到的样子，不用等编译、不用重装。

如果 iPad 打不开，检查 Windows 防火墙是否放行了 Node：

```powershell
New-NetFirewallRule -DisplayName "Vite Dev Server" -Direction Inbound -LocalPort 5173 -Protocol TCP -Action Allow
```

## 4. iPad 添加到主屏幕

1. Safari 打开部署地址（必须是 **Safari**，Chrome 版 iOS 不支持添加 PWA）
2. 点击底部工具栏的**分享按钮** <kbd>⬆️</kbd>
3. 下滑找到「**添加到主屏幕**」
4. 确认名称（默认「希恩爱学习」）→ 添加
5. 主屏幕出现橙色星星图标，点开即全屏运行

### 验证是否成功

打开后应满足：

- [ ] **没有 Safari 地址栏和底部工具栏**（全屏 standalone）
- [ ] 状态栏时间/电量正常显示
- [ ] 点「开始学习」能出题
- [ ] **能听到语音朗读题目** ← 最关键
- [ ] 开飞行模式后仍能打开并答题（离线可用）

## 5. 更新流程

```powershell
npm run deploy      # = build + deploy-pages.mjs 推到 gh-pages 分支
```

### 5.1 新版本何时生效

进 App 后，只要**不在答题中**（会话状态为 `idle`，即首页、宠物页、家长区这些地方），
等待中的新版本会自动接管并刷新一次页面，通常在打开后一两秒内完成。

答题途中（`active` / `feedback`）与小结页（`finished`）**绝不接管**：
当前这段题目存在内存里，刷新会全部丢失，孩子会觉得「刚才做的都白做了」。
实现见 `src/platform/appUpdate.ts` 与 `src/App.tsx` 里那个 effect。

### 5.2 ⚠️ 历史故障：更新连续多个版本推不下去

2026-08 曾出现「部署了新版本，iPad 上点开图标还是旧的」，
连着几个版本都更新不上，最后只能删掉主屏幕图标重装——
而重装会清掉本机 IndexedDB，孩子几百道题的进度全靠备份文件找回。

根因是一对**自相矛盾**的配置：

```ts
registerType: 'autoUpdate'   // 只负责把新 SW 下载到 waiting
skipWaiting: false           // 又不许它接管
```

`autoUpdate` 生成的注册脚本只做周期性 `registration.update()`，
把新 Service Worker 下载进 **waiting** 就结束了；真正让它上任的 `skipWaiting()`
被关掉了。当时以为「等下次冷启动自然生效」——**并不会**：
waiting 的 SW 要等**所有**受控页面关闭才激活，而 iOS 上 PWA 转入后台时
页面并没有销毁，这个条件常年不成立。

现在改为 `registerType: 'prompt'`，由 App 在会话空闲时主动发 `SKIP_WAITING`，
见 §5.1。

> 教训：**更新能不能落地，本身就是数据安全问题**。
> 进度全在本机，一旦有人为了拿到更新去重装，那份进度就只剩备份文件一条退路了。

## 6.1 备份进度（⭐ 换设备/清数据前必做）

数据全在 iPad 本地。清一次 Safari 数据、换一台设备，进度就没了。备份是唯一的保险。

**进入家长区**：主页**右上角长按 3 秒**（没有可见按钮，孩子不会误入）
→ 答一道两位数进位加法（如 `58 + 26`）→ 进入导航页
（📊 学习报告 · 📕 错题本 · 💾 数据备份）。

> 门禁在同一次会话内只需答一次，三个页面之间来回切换不会重复验证；
> 点「回主页」即收回通行证，下次进来要重新答题。

**保存**：点「💾 数据备份」→「💾 保存进度到文件」

- iPad 会弹出系统分享面板，可 **AirDrop 到另一台设备** / 存 **iCloud Drive** / 发给自己
- 不支持分享时降级为下载，文件进「文件」App
- 文件名形如 `希恩爱学习_小恩宝_2026-08-06.json`，约几 MB

**恢复**：点「📂 选择备份文件」→ 选中 json → **核对确认卡上的题数与日期** → 「确认恢复」

> ⚠️ 恢复是**整体替换**：会用文件里的进度覆盖这台设备上现有的全部进度，无法撤销。
> 确认卡就是为了防止导错文件，务必看一眼再点。

**建议节奏**：每周一次，或每次孩子有明显进步时。超过 7 天没备份，家长区会主动提示。

> 备份文件**只含孩子的学习记录，不含题库**。因此三个月前的备份可以导进内容更多的新版本 App，
> 新增的知识点会自动补上，不会被旧内容覆盖。

## 7. 故障排查

### 听不到声音 ⭐ 最常见

iOS 要求语音合成必须在**用户手势中首次触发**。App 已通过「开始学习」按钮解锁。

- 确认 iPad **静音开关**没打开（侧边实体开关）
- 确认音量不是 0
- 回到主页重新点一次「开始学习」
- 仍无声：设置 → 辅助功能 → 朗读内容 → 确认已下载中文语音

### 添加到主屏幕后打开是白屏

多为 Service Worker 缓存了不完整的旧版本：

1. 长按图标删除
2. 设置 → Safari → 清除历史记录与网站数据
3. 重新用 Safari 打开地址，再添加

### 「今天没有需要练习的内容」

正常情况不会出现。若出现，说明所有可出题的知识点都已掌握且未到复习期。
当前只有 28 个数学知识点，孩子练熟后会遇到。属于内容量不足，等 ⑧ ⑨ 补充。

### 进度突然清零

大概率是没有添加到主屏幕，Safari 清了网站数据。见本文 §0。

### 想重置全部数据重新开始

Safari 里打开地址 → 分享 → 无痕/清除数据，或在开发者控制台执行：

```js
await indexedDB.deleteDatabase('smartlearning')
```

## 8. 上机后要观察什么

这个阶段的**唯一目标**是回答一个问题：

> **她会不会主动打开第二次？**

建议观察并记下：

- 第一次玩了多久？是主动停下还是被叫停？
- 第二天会不会自己要求玩？
- 哪种题型她反应最快、最有兴趣？（数数 / 比大小 / 分与合 / 加减法）
- 答错时的反应——是继续尝试，还是有挫败情绪？
- 有没有看不懂界面、不知道该点哪里的时刻？

**这些观察比后面所有功能开发都重要。** 如果她不感兴趣，
先调整的应该是内容和反馈设计，而不是继续堆功能。
